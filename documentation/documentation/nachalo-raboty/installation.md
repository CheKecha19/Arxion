# Установка и обновление

## Что потребуется

Для готовой поставки нужен компьютер Windows и доступ на чтение конфигураций и запись пользовательских данных. Отдельно устанавливать Python для полной Windows-поставки не требуется. Для API-сбора необходима сетевая доступность выбранного сервиса и учётные данные с необходимыми правами.

Точный минимальный объём RAM, диска и матрица поддержанных выпусков Windows не установлены измерениями проекта. Не рассчитывайте ёмкость рабочего места по неподтверждённым обещаниям о числе устройств или правил.

## Готовая поставка

1. Получите полную папку приложения для нужной версии из согласованного канала поставки. Список опубликованных версий доступен в [GitHub Releases](https://github.com/CheKecha19/Arxion/releases). На 13 ноября 2026 года у v0.10.0 нет прикреплённых бинарных файлов: готовую папку нужно получить у сопровождающего проекта либо подготовить сборку из исходников.
2. Сохраните её в локальный каталог. В папке должны находиться EXE, каталог `_internal` и `README.txt`.
3. Запустите `FirewallComplience_v<версия>.exe` из этой папки.
4. Создайте проект кнопкой **Новый проект**.

Например, для версии 0.10.0 папка называется `FirewallComplience_v0.10.0`, а файл внутри неё — `FirewallComplience_v0.10.0.exe`. Автоматические архивы исходников GitHub не являются готовой Windows-поставкой. Наличие версии в исходниках также не означает, что её бинарная сборка опубликована.

## Обновление

1. Дождитесь завершения операций в **Задачах** и закройте приложение.
2. Сохраните резервную копию базы и исходных конфигураций по [инструкции хранения](../rabochee-prostranstvo/storage.md).
3. Разместите полную папку новой версии отдельно от старой.
4. Запустите новую версию под тем же пользователем Windows.
5. Проверьте проекты, историю и настройки подключений. При сообщении о недоступном секрете введите его повторно.
6. Выполните осознанный новый импорт, если нужны сведения, которые старый парсер не сохранял.

Старые снимки не обогащаются новыми сведениями автоматически. Возврат к старому EXE не гарантирует совместимости с уже изменённой базой: для отката используйте копию базы, сделанную до обновления, вместе с соответствующей версией приложения.

## Запуск из исходников

Для инженеров, которым нужен CLI или рабочая версия: требуется Python **3.12 или новее**, uv и исходники проекта. В каталоге проекта подготовьте зависимости из lock-файла:

```powershell
uv sync --locked --all-groups
uv run firewall-compliance-desktop
```

Это команды для самостоятельного развёртывания, а не действия, выполненные при написании руководства. Установка зависимостей требует доступа к источникам пакетов. CLI запускается через `uv run firewall-compliance`. Отдельная CLI-поставка не предусмотрена.

## Если окно не открывается

Проверьте целостность папки и наличие `_internal`, убедитесь, что запускаете EXE выбранной версии. Сохраните текст ошибки и версию. Не заменяйте отдельные DLL файлами от другой сборки. Если проблема появилась после обновления, сохраните новую базу перед восстановлением резервной копии.
