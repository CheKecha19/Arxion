# Первая проверка

Цель сценария — получить воспроизводимый результат по одному файлу и научиться читать его ограничения.

## Подготовьте входные данные

Используйте экспорт конфигурации поддержанной платформы, который разрешено анализировать на этом компьютере. Сохраните неизменную копию файла и дату получения. Для знакомства выберите небольшой синтетический пример. Произвольный резервный архив производителя не обязательно является поддержанным форматом.

## Выполните анализ

1. Нажмите **Новый проект**, введите, например, «Учебный стенд».
2. Нажмите **Добавить данные** и выберите файл конфигурации. Для выбора файла также доступно **Ctrl+O**, папки — **Ctrl+Shift+O**.
3. Откройте **Источники данных → Файлы и запуск**. Проверьте выбранные файлы, распознанную платформу, идентификаторы устройств и предупреждения. Не продолжайте сравнение с прежними данными, если вместо нужного устройства выбран другой источник.
4. В **Настройки → Проверки** выберите нужные проверки и сохраните настройки. Для первой оценки используйте понятный вам профиль; исключённые проверки не дадут выводов.
5. Нажмите **Запустить проверку файлов**. Состояние операции смотрите в **Задачах**.
6. По завершении откройте **Анализ → Проверки**. Изучите ошибки обработки, ограничения и только затем найденные проблемы.
7. Выберите находку и откройте связанные доказательства. Сопоставьте правило и строки исходной конфигурации.
8. Перейдите в **Отчёты**, выберите соответствующий результат и нужный формат экспорта. Сохраните отчёт рядом с записью о времени и источнике проверки.

Общая команда **Обновить и проверить** предназначена для цикла с подключёнными источниками и файлами. Перед подтверждением проверяйте его состав: он может включать сетевой сбор.

## Как оценить результат

Для примера рассмотрим правило, разрешающее TCP/443 из `192.0.2.0/24` к `198.51.100.10`. Адреса здесь учебные. Если правило найдено, это подтверждает наличие соответствующего объявления в разобранной конфигурации. Доступность приложения на сервере, маршруты и поведение промежуточных устройств из этого автоматически не следуют.

Если находок нет, проверьте: выполнены ли нужные проверки, распознаны ли правила, достаточно ли данных, нет ли статуса неполноты. Ошибка одного файла не превращается в успешный пустой результат всего набора.

## Что сохранить

Оставьте исходный файл, отчёт и сведения о профиле проверки. Для повторного открытия исходника старой ревизии нужен файл с тем же SHA-256 — цифровым отпечатком содержимого. Исправленный файл добавляйте как новый вход и анализируйте заново.
