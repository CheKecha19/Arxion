# Cloud.ru

Arxion различает платформы VMware, Advanced и Evolution. Настройки и возможности анализа у них разные.

| Платформа | Что получает Arxion                                                                                   | Что анализирует                                       |
| --------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| VMware    | ВМ, Edge Gateway, Org VDC networks; дополнительные Firewall, NAT, static routes и сетевые подключения | Поддержанный срез NSX-T Edge Firewall                 |
| Advanced  | ECS, VPC, подсети, Security Groups                                                                    | Инвентаризация; общий анализ качества SG не подключён |
| Evolution | ВМ, подсети, интерфейсы, Security Groups                                                              | Инвентаризация; общий анализ качества SG не подключён |

## Настройка подключения

Выберите проект, затем откройте **«Настройки → Интеграции → Cloud.ru»** и нужную платформу.

### VMware

Заполните:

* **«Адрес площадки»** — HTTPS-адрес Cloud Director или ссылка с `/tenant/…/`;
* **«Tenant»** — имя организации;
* **«API Token»**;
* **«Версия API»** — автоматически либо явно;
* **«Таймаут запроса»**.

Нажмите **«Сохранить подключение»**, затем при необходимости **«Проверить подключение»**. Пустое поле токена при редактировании сохраняет прежний токен.

Сбор ограничен правами токена. Выбор отдельного Org VDC в качестве фильтра сбора не реализован.

### Advanced

Укажите **Project ID**, постоянные **Access Key (AK)** и **Secret Key (SK)**, регион. При необходимости задайте HTTPS-адреса ECS API и VPC API, а также таймаут.

Для подписанных запросов требуется корректное системное время. Временные ключи с Security Token не поддерживаются.

### Evolution

Укажите UUID проекта в **Project ID**, **Key ID**, **Key Secret** и таймаут запроса. Сохраните подключение и проверьте его.

Ключи защищаются Windows DPAPI в контексте текущего пользователя Windows. Перенос базы на другой компьютер или в другой профиль не следует считать переносом работоспособных секретов.

Облачный транспорт проверяет HTTPS-сертификаты и не следует перенаправлениям. Для ошибки сертификата исправьте доверие и адрес подключения; режима отключения проверки в этих формах нет.

## Сбор и просмотр

Откройте **«Источники данных → Облачный сбор»**, выберите источник, типы ресурсов и дополнительные данные. Нажмите **«Запустить сканирование»**.

После завершения используйте:

* **«Открыть результат сбора»** — ресурсы и диагностика;
* **«Экспорт JSON»** — сохранение полученных данных;
* **«Проверить правила сохранённого сбора»** — поддержанный анализ VMware Edge Firewall;
* **«Открыть проблемы и результаты проверок»** — переход к результатам анализа.

Повторный анализ сохранённого VMware-снимка не требует нового обращения в облако. При этом он использует именно сохранённые данные, которые могут отличаться от текущей конфигурации.

**«Отменить сканирование»** запрашивает остановку. Уже полученные данные и статус операции необходимо проверять отдельно: отмена не превращает результат в полный снимок.

## Что нельзя заключать по облачному сбору

Наличие Security Groups в инвентаре Advanced/Evolution не означает, что правила прошли firewall-проверки.

Для VMware не поддержаны DFW, NSX-V, гостевые NGFW, динамические маршруты и effective NAT. Собранное NAT-правило не является доказательством разрешённого доступа. Отсутствующий объект может быть недоступен учётной записи или не включён в сбор.

## Если подключение или сбор не удались

При отказе авторизации проверьте учётные данные и область их прав. Для VMware сверьте tenant и площадку; для Evolution — UUID проекта; для Advanced — IAM Project ID, регион и часы компьютера. При таймауте проверьте сеть, VPN и прокси, затем допустимость увеличения таймаута. При частичном сборе откройте диагностику конкретных ресурсов: успешные части не подтверждают полноту всего результата.

## Разработка поддержки Security Groups

В текущем рабочем дереве появилась основа нормализации SG Advanced/Evolution и проекции выбранной группы, интерфейса, направления и семейства адресов для матрицы доступа. Это ещё не подключённый пользовательский сценарий: автоматический анализ облачного сбора и кнопка повторной проверки по-прежнему ограничены VMware Edge Firewall. Поэтому наличие этих модулей не означает, что SG прошли проверки.

Подготовленная проекция требует однозначной привязки группы к интерфейсу, подтверждённых адресов и сохранённого исходного сбора; для Evolution в ней предусмотрен только IPv4. Удалённые ссылки на SG и адресные группы не заменяются произвольными адресами. Эта работа пока не является гарантией вычисления совокупной политики нескольких SG, stateful-поведения или сквозной достижимости.
