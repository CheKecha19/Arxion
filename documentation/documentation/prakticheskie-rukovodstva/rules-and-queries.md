# Правила и запросы

## Просмотр правил

В разделе правил выберите область данных:

* «Все ресурсы проекта · последние снимки»;
* «Выбранный запуск».

Дополнительно используйте фильтр назначения правил. Не смешивайте транзитные ACL, управление устройством и правила без подтверждённого применения: одинаковые условия адресов не означают одинаковое воздействие на сеть.

## Поиск по условиям

1. Укажите IP/CIDR источника и назначения.
2. Выберите протокол.
3. Для TCP/UDP при необходимости задайте порты назначения, например `443,1000-2000`.
4. Оставьте «Сохранять неизвестные условия» включённым, чтобы не скрывать правила, которые невозможно однозначно сопоставить.
5. Нажмите «Применить условия»; в компактном представлении кнопка называется «Применить».

CIDR в запросе означает пересечение условий. Найденное правило не обязательно целиком покрывает указанный диапазон.

Например, запрос `192.0.2.0/24 → 198.51.100.20`, TCP/443 помогает найти пересекающиеся условия правил. Он не проверяет работоспособность сервиса и не вычисляет маршрут через сеть.

«Сбросить условия» возвращает исходный просмотр. Если правила не найдены, проверьте область данных, категорию, выбранную ревизию и отображение неизвестных условий.

## Запрос к роли ArubaOS Controller

Для поддерживаемых конфигураций контроллера доступна оценка роли по конкретному источнику, назначению и сервису. Дополнительный контекст может включать время, IP пользователя, локальный IP, сведения о ролях адресов и группу AP.

Для уверенного вычисления нужен подтверждённый полный effective-экспорт. При недостатке данных ответ остаётся неизвестным. Вывод относится к поддерживаемой локальной политике роли; маршрутизация, полная трансляция и DPI-классификация этим запросом не доказываются.
