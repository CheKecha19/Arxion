# Матрица доступа

Матрица доступа описывает требования организации: какие группы должны иметь доступ друг к другу, по каким протоколам и портам. Arxion сопоставляет сохранённую версию требований с конкретной ревизией конфигурации.

Матрица не изменяет настройки оборудования. Результат сверки относится к выбранному снимку и поддерживаемой семантике правил; он не подтверждает прохождение трафика через всю сеть.

## Открытие матрицы

1. Выберите сохранённый проект и нужную область просмотра.
2. Откройте страницу «Матрица доступа» и нажмите «Открыть матрицу доступа…». Матрица также доступна через «Действия с правилом / объектом» → «Матрица доступа…».
3. В окне «Данные для сверки матрицы» найдите снимок по устройству, платформе или времени.
4. Выберите снимок либо «Редактор без выбранного снимка».

Без выбранной ревизии можно готовить требования и версии матрицы, но сверка недоступна. Перед работой проверьте показанные в окне ревизию, область и профиль.

## Группы

На вкладке «Группы» задайте участников каждой группы. У группы есть стабильный ID и понятное название. Название само по себе не определяет её состав и не связывает группу с Active Directory.

Поддерживаются участники следующих видов:

* IP-адрес или подсеть CIDR;
* объект конфигурации по ID из выбранной ревизии;
* другая группа матрицы по ID;
* логическая сеть проекта по ID;
* ресурс проекта по ID.

Используйте «Добавить участника» для явного ввода. «Добавить из каталога проекта» позволяет искать ресурс или логическую сеть по части названия либо ID.

Пример: группа `employees` содержит `192.0.2.0/24`, а группа `portal` — `198.51.100.20/32`. Эти адреса приведены исключительно как синтетический пример.

Связь с объектом конфигурации проверяется в выбранном снимке. Наличие имени в каталоге ещё не гарантирует возможность разрешить объект в адреса для сверки. В текущем подключении каталожные адресные привязки ограничены снимками с фактами коммутатора и без нестандартного VRF. Неразрешённые ссылки требуют проверки исходных данных.

## Требования

На вкладке «Требования»:

1. Нажмите «Новое требование».
2. Задайте уникальный ID, группы источника и назначения, область и ID политики для сверки.
3. Выберите протокол: TCP, UDP, ICMP или IP.
4. Для портов используйте одиночные значения, диапазоны и списки, например `443,1000-2000`; `*` означает любые порты.
5. Выберите вид требования.
6. При необходимости укажите владельца, основание, дату пересмотра, пользователя/группу и условие расписания.
7. Нажмите «Применить карточку к черновику».

| Требование          | Значение                                                  |
| ------------------- | --------------------------------------------------------- |
| Доступ необходим    | Указанный доступ должен быть предусмотрен                 |
| Доступ допустим     | Доступ разрешён требованиями, но не объявлен обязательным |
| Запретить           | Указанный доступ не должен разрешаться                    |
| Не регламентировано | Требование к этому доступу не установлено                 |

Пример: требование `employees-portal-https` связывает `employees` с `portal`, протокол TCP, порт 443, действие «Доступ необходим». ID политики необходимо взять из реальной выбранной ревизии: произвольное название не привяжет требование к ACL.

«Применить карточку к черновику» изменяет только редактируемый черновик. Для сохранения нужна новая версия матрицы.

Для поиска требований используйте поля «Откуда · имя или ID» и «Куда · имя или ID», затем «Найти». «Удалить из черновика» убирает выбранное требование. Если на него ссылается ограничение, сначала исправьте эту ссылку.

## Только перечисленный доступ

Отсутствие требования по умолчанию означает «не регламентировано», а не «запрещено».

Чтобы ограничить область только перечисленными разрешениями, используйте отдельную вкладку «Только перечисленный доступ». Здесь можно добавить, изменить или убрать ограничение, определяющее область и разрешённый набор требований. Это позволяет искать лишние разрешения в явной области контроля.

Перед удалением или переименованием требования проверьте ограничения, которые на него ссылаются.

## Черновик из существующих правил

«Черновик из правил…» помогает подготовить требования на основании выбранной ревизии и политики. Полученный черновик необходимо проверить вручную: существующая конфигурация показывает реализованные условия, но не заменяет утверждённые требования организации.

Исправьте состав групп, обязательность доступа, владельцев и основания. Затем сохраните новую версию.

## Сохранение и сверка

1. Нажмите «Проверить структуру».
2. Исправьте отсутствующие группы, некорректные поля и конфликты требований.
3. Нажмите «Утвердить и сохранить новую версию».
4. Проверьте выбранную ревизию.
5. Нажмите «Сверить с выбранной ревизией».

Если после сохранения вы изменили черновик, сначала сохраните изменения новой версией. Приложение не разрешает выдавать сверку несохранённого черновика за результат сохранённой версии.

Во время вычисления доступна кнопка «Остановить сверку». Остановка происходит после текущего участка работы. Частичный или остановленный результат нельзя трактовать как завершённую проверку всей матрицы.

## Интерпретация результатов

| Результат                            | Что проверить                                                                                 |
| ------------------------------------ | --------------------------------------------------------------------------------------------- |
| Покрывающее заданное условие найдено | Сверьте режим вычисления и доказательства; это не всегда решение реально применяемой политики |
| Противоположное заданное условие     | Изучите правило с противоположным действием и область его применения                          |
| Частичное покрытие                   | Определите, какие адреса или сервисы покрыты, а какие остались вне покрытия                   |
| Лишнее разрешение                    | Проверьте разрешение за пределами перечисленного доступа в явном ограничении                  |
| Недостаточно данных                  | Проверьте разрешение групп, полноту снимка, поддерживаемость условий и диагностику            |
| Конфликт требования                  | Исправьте противоречащие друг другу требования                                                |
| Другая область                       | Проверьте, соответствует ли область требования выбранной сверке                               |
| Не регламентировано                  | Решите, требуется ли отдельное правило организации для данного доступа                        |

Выберите строку, чтобы прочитать основание и доказательства. Фильтр результата помогает сосредоточиться на конфликтах, недостатке данных или лишних разрешениях.

Сверка различает режимы:

* **Условия правил** — сопоставление объявленных условий;
* **Локальная политика** — поддерживаемое вычисление локального решения с учётом подтверждённого применения ACL;
* **Смешанный** — в результате использованы оба подхода.

Даже локальное решение не вычисляет полный маршрут, NAT, обратное направление или сквозной доступ. Неявный запрет учитывается только при наличии достаточных подтверждающих данных; неизвестные условия нельзя считать разрешением или запретом по умолчанию.

## История и отчёты матрицы

В списке сохранённых версий выберите нужную версию. «Перечитать историю» обновляет список.

В блоке «Сохранённые сверки»:

* «Открыть результат» открывает выбранную историческую сверку;
* «Сравнить с открытой сверкой» сопоставляет её с уже открытой;
* «← Новее» и «Старее →» переключают страницы истории.

«Сетка групп × групп» показывает матрицу в табличном представлении.

Для передачи результатов используйте «Предпросмотр результата» и «Сохранить HTML», «Сохранить JSON» или «Сохранить CSV». Отчёт относится к сохранённой сверке и сохраняет связь с матрицей и ревизией; экспорт не является новым вычислением доступа.

## Копирование и перенос черновиков — изменения в разработке

Следующие действия подключены к редактору в незавершённых изменениях рабочего дерева. Их наличие в опубликованной или ранее собранной версии не подтверждено. Описание основано на статическом просмотре кнопок, сигналов и обработчиков; выполнение не проверялось.

### Копирование требований

1. На вкладке «Требования» при необходимости отфильтруйте строки по источнику и назначению.
2. Нажмите «Копировать…».
3. Выберите «Выбранная строка» либо «Текущая выборка целиком». Полная выборка включает строки со всех страниц, а не только видимые строки.
4. Выберите, что заменить в копиях: источники или назначения.
5. Добавьте существующие группы либо укажите по одному ID группы на строку.
6. Нажмите «Предварительный просмотр».
7. Проверьте таблицу и нажмите «Добавить в черновик».
8. Утвердите изменения новой версией матрицы.

Для каждой выбранной строки создаётся копия на каждую целевую группу. Область, политика, сервис и дополнительные условия сохраняются. Ограничения «Только перечисленный доступ» автоматически не копируются и редактируются отдельно.

Предпросмотр показывает, что добавится, совпадает или противоречит существующим строкам. Совпадения и противоречия пропускаются. Здесь сопоставляются ID групп и сервисные условия; пересечения фактического состава разных групп и закрытых областей требуют отдельной проверки при сверке матрицы.

### Экспорт черновика

«Экспорт черновика…» сохраняет JSON-пакет matrix-draft.json. Он содержит матрицу, исходный проект, выбранную ревизию при её наличии и разрешённые адресные привязки каталога.

Это переносимый черновик требований, а не отчёт выполненной сверки и не утверждённая версия. Для сохранения в историю по-прежнему используется «Утвердить и сохранить новую версию».

### Импорт черновика

1. Сохраните либо экспортируйте текущий черновик, если его требуется оставить.
2. Нажмите «Импорт черновика…» и выберите JSON-файл.
3. Проверьте количество групп, требований, ограничений и области из файла.
4. Выберите «Заменить черновик» либо отмените операцию.
5. Если в файле одна область и она отличается от текущей, можно выбрать «Заменить и перенести в текущую область».
6. Проверьте ID политик, состав групп и область; затем сохраните новую версию.

Импорт заменяет текущий черновик в редакторе. Перенос области изменяет области требований и ограничений, но не угадывает соответствие политик и оборудования.

Ссылки на объекты конфигурации можно импортировать только в ту же ревизию того же проекта. В том же проекте ссылки на ресурсы и логические сети оцениваются по текущему каталогу. При переносе в другой проект такие ссылки заменяются явными адресами, сохранёнными в пакете. Если адресная привязка отсутствует, перенос отклоняется. После преобразования адреса становятся фиксированным составом и не отслеживают изменения исходного каталога.
