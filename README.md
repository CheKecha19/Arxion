# Firewall Compliance

Локальное рабочее место для анализа конфигураций межсетевых экранов и сетевого оборудования. Приложение помогает находить проблемы в правилах доступа, разбирать их причины, отслеживать изменения и готовить отчёты с доказательствами.

Проект предназначен для сетевых инженеров и специалистов по информационной безопасности. Основной интерфейс — настольное приложение для Windows на PySide6 / Qt; для автоматизации доступен CLI.

**Статус:** активная разработка до v1.0. Поддержка платформ ограничена конкретными форматами и конструкциями. Результаты содержат сведения о полноте разбора и границах каждой проверки.

## Возможности

- **Анализ конфигураций.** Импорт отдельных файлов и папок, определение формата по содержимому, разбор правил, адресных объектов и сервисов. Ошибки отдельных файлов сохраняются в результатах пакетной обработки.
- **Проверки правил доступа.** Широкие разрешения any-any, дубликаты, полное затенение одним правилом, кандидаты на объединение, отсутствие журналирования и описаний, отключённые правила. Дополнительно включаются проверки частичного и составного затенения, сервисов и областей доступа по заданному профилю.
- **Проверки управления устройствами.** Для поддержанных конфигураций HP/Aruba и Comware — Telnet/HTTP, источники администрирования, SNMP, syslog, NTP, тайм-ауты и баннер. Требования настраиваются профилем.
- **Разбор проблем.** Критичность, объяснение, рекомендация, связанные правила и фрагменты источника. Пользователь может назначать статусы, оставлять комментарии и просматривать историю решений.
- **Проекты и инфраструктура.** Сохранённые результаты и ревизии, реестр устройств и облачных ресурсов, ручные подписи, размещение и архивирование ресурсов.
- **Карта.** Карта проекта и представление заданных условий ACL с фильтрами и переходами к правилам. Карта помогает изучать конфигурацию; её связи не доказывают фактическую доступность по сети.
- **Интеграции.** Чтение данных Cloud.ru VMware, Advanced и Evolution; сбор снимков UserGate и Ideco для последующего анализа. Для VMware Edge Firewall доступны проверки правил.
- **Отчётность.** HTML и JSON для результатов запусков; JSON, CSV и HTML для общего результата анализа. Технические контроли и метаданные правил позволяют учитывать требования организации, владельцев и основания правил.

## Источники данных

| Источник | Что доступно | Основные ограничения |
| --- | --- | --- |
| Cisco ASA 9.16 | Импорт ACL, объектов и групп, проверки правил; отдельные сетевые инструменты | Поддерживается часть синтаксиса; сквозная достижимость не вычисляется |
| HP/Aruba AOS-Switch и AOS-CX | IPv4 ACL, привязки и настройки управления | Транзитные ACL и ограничения административного доступа анализируются раздельно |
| HP/H3C Comware | IPv4 ACL, правила и настройки управления | Ограниченный набор конструкций; SNMP ACL относятся к управлению устройством |
| UserGate NGFW | Сбор через XML-RPC и импорт снимка `arxion-usergate-v1` | Профили UGOS 6.1.5+ в ветке 6 и UGOS 7; совместимость с реальными прошивками ещё не подтверждена |
| Ideco NGFW v23 | Сбор через HTTPS API и импорт снимка `arxion-ideco-v1` | Классический VCE; VPP/BPF и Ideco Center не поддержаны; работа с реальным устройством ещё не подтверждена |
| Cloud.ru VMware | Инвентаризация ВМ, Edge Gateway и сетей, сбор сетевых конфигураций, анализ Edge Firewall | Неизвестные группы и условия ограничивают полноту проверки |
| Cloud.ru Advanced и Evolution | Сбор облачного инвентаря через API | Наличие ресурса в инвентаре само по себе не означает проверку его правил |

UserGate и Ideco принимаются через снимки собственных коллекторов приложения; это не обещание поддержки произвольных резервных копий производителя. ArubaOS controller session ACL/user-role и Juniper Junos/SRX не подключены к стандартному импорту CLI и desktop.

Параметры подключения и ограничения: [UserGate](specifications/USERGATE.md), [Ideco](specifications/IDECO.md), [Cloud.ru VMware](specifications/CLOUD_RU_VMWARE.md), [Cloud.ru Advanced и Evolution](specifications/CLOUD_RU_PUBLIC.md).

## Быстрый старт

### Запуск из исходников

Нужны Windows 10/11 x64, Python 3.12+ и установленный `uv`. Выполните из корня репозитория:

```powershell
uv sync --locked --all-groups
uv run firewall-compliance-desktop
```

После установки зависимостей также можно запускать приложение через `Start-Desktop.cmd`.

### Первый анализ в приложении

1. Создайте проект или выберите существующий.
2. Нажмите **«Добавить данные»** и добавьте файлы конфигураций или папку.
3. В **«Операции → Файлы и проверки»** проверьте определённые форматы, идентификаторы устройств и предупреждения.
4. Настройте необходимые проверки в **«Настройки → Правила»**, затем нажмите **«Запустить проверку файлов»**.
5. Откройте результат: изучите проблемы, связанные правила и доказательства. Проверьте также полноту анализа и ошибки импорта.
6. В **«Отчёты»** выберите нужный запуск и сохраните HTML или JSON.

Облачные подключения настраиваются в **«Настройки → Интеграции → Cloud.ru»**, сбор запускается в **«Операции → Облачный сбор»**. UserGate и Ideco доступны через отдельные действия на странице файлов и проверок: полученный JSON добавляется для обычного анализа.

### Portable-сборка

Откройте `FirewallComplience_v<версия>.exe` из папки `dist/FirewallComplience_v<версия>`. Переносите всю папку, включая `_internal`; Python и `uv` для запуска не требуются.

Для сборки из подготовленного окружения на Windows:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_desktop.ps1
```

Результат появится в `dist/FirewallComplience_v<версия>`, где версия берётся из `pyproject.toml`. Повторная сборка перезаписывает эту папку. Архив автоматически не создаётся; отдельные CLI/feature-сборки не выпускаются. См. [правила сборки](specifications/WINDOWS_DISTRIBUTION.md).

## CLI

Анализ одного файла с выводом JSON в терминал:

```powershell
uv run firewall-compliance analyze "C:\configs\device.cfg"
```

Сохранение общего результата и создание HTML-отчёта:

```powershell
uv run firewall-compliance analyze-bundle "C:\configs\device.cfg" --output analysis.json
uv run firewall-compliance analysis-export analysis.json --format html --output report.html
```

Дополнительные проверки политики включаются явно:

```powershell
uv run firewall-compliance analyze "C:\configs\device.cfg" --extended-policy-checks
```

Параметры `--management-profile`, `--policy-exposure-profile` и `--policy-scope-profile` принимают JSON-профили. Требования к журналированию и описаниям можно отключить через `--no-require-logging` и `--no-require-comments`. Флаг `--complete-config` используйте только при наличии полного экспорта: это подтверждение пользователя, а не автоматическая проверка полноты файла.

Справка по командам и параметрам:

```powershell
uv run firewall-compliance --help
uv run firewall-compliance analyze --help
```

Также доступны группы `acl-map`, `controls`, `governance` и команды сбора `usergate-collect`, `ideco-collect`. Пароли для этих двух коллекторов запрашиваются интерактивно.

Для `analyze` код выхода `0` означает, что результат сформирован: он может содержать проблемы и частично выполненные проверки. Ошибки чтения, распознавания или разбора возвращают код `2`. Наличие проблем следует проверять по содержимому JSON.

## Как читать результаты

Приложение разделяет найденные проблемы и полноту проверки:

| Статус | Значение |
| --- | --- |
| `complete` | Проверка выполнена в поддержанной области |
| `partial` | Часть условий неизвестна, не поддерживается или не может быть проверена |
| `not_applicable` | Проверка неприменима к данной области |

Ноль находок не означает, что конфигурация безопасна. Неизвестные адреса, неподдержанные условия и отсутствующие ссылки на объекты не превращаются в разрешение «любой».

Анализ описывает настроенные правила и доступные свидетельства. Он не подтверждает сквозную достижимость с учётом NAT, маршрутизации и оперативного состояния всей сети. Технические контроли помогают оценивать выбранные требования организации, но не являются сертификацией соответствия стандартам.

## Хранение данных

Проекты, история, настройки и пользовательские решения по умолчанию сохраняются локально в:

```text
%LOCALAPPDATA%\FirewallCompliance\projects.sqlite3
```

База хранит нормализованные снимки и ограниченные фрагменты источников. Для просмотра полного исходного файла после перезапуска потребуется подключить файл с тем же SHA-256; изменённая конфигурация анализируется как новый источник.

Файловый анализ выполняется локально. Подключение к API запускается пользователем для чтения данных; коллекторы не изменяют конфигурацию оборудования. Снимки API, база и отчёты могут содержать внутренние адреса и другие чувствительные сведения — учитывайте это при хранении и передаче.

## Разработка

Основной стек: Python, PySide6 / Qt, Pydantic и SQLite. Окружение и зависимости управляются через `uv`, форматирование и линт — Ruff, типизация — mypy.

Реализации платформ находятся в `src/firewall_compliance/devices`, проверки — в `src/firewall_compliance/checks`. Общие модели, прикладные сценарии, инфраструктура и интерфейсы разделены по слоям. Прежние пути импорта сохранены как совместимые псевдонимы. Временные кэши и результаты сборок размещаются в `_temp_files`; тесты и свидетельства проверок хранятся отдельно.

Правила внесения изменений и объём проверок описаны в [AGENTS.md](AGENTS.md). Перед изменениями учитывайте текущие ограничения разработки до v1.0.
