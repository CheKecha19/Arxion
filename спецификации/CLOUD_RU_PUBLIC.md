# Cloud.ru Advanced и Evolution

Обе платформы доступны в Настройки → Интеграции → Cloud.ru и в источниках
Операции → Облачный сбор → Новый сбор. Подключения хранятся отдельно для каждого локального
проекта и каждой платформы. VMware продолжает работать независимо.

## Параметры

| Платформа | Обязательные поля | Дополнительные поля |
| --- | --- | --- |
| Evolution | Key ID, Key Secret, UUID облачного проекта | Таймаут (30 секунд по умолчанию) |
| Advanced | Постоянные AK, SK, IAM Project ID (32 hex-символа), регион | Адреса ECS/VPC API, таймаут |

Evolution: ключ доступа создаётся для сервисного аккаунта или пользователя.
Нужны права чтения выбранных ресурсов Compute. IAM и Compute адреса задаются
приложением автоматически. Перед каждым запуском выполняется обмен ключей на
Access Token через `POST https://iam.api.cloud.ru/api/v2/auth/token` с JSON
`{"keyId": "...", "secret": "..."}`; дальше используется Bearer-авторизация.
[Официальная авторизация](https://cloud.ru/docs/administration/ug/topics/api-ref__authentication).

Advanced: AK/SK создаются в My Credentials → Access Keys. Project ID берётся
в My Credentials → API Credentials; это IAM Project ID, а не Enterprise Project
ID. Нужны права чтения ECS и VPC. Регион по умолчанию — `ru-moscow-1`.
При пустых адресах используются `https://ecs.<регион>.hc.sbercloud.ru` и
`https://vpc.<регион>.hc.sbercloud.ru`. Допустимы соответствующие региону адреса
ECS/VPC в `hc.cloud.ru`. Запросы подписываются SDK-HMAC-SHA256 с X-Sdk-Date и
X-Project-Id. Часы компьютера должны быть синхронизированы.
Временные AK/SK с Security Token, парольная IAM-авторизация и федерация пока
не поддержаны. [Официальная авторизация Advanced](https://cloud.ru/docs/en/api/vpc/vpc_api00_0010?source-platform=Advanced).

Обе части ключа защищаются Windows DPAPI. В форме они не показываются повторно
и не попадают в историю, JSON или настройки проверок. Пустые поля сохраняют
прежний ключ при изменении таймаута. Для смены облачного проекта, региона или
адреса API нужно ввести обе части заново.

## Состав сканирования

Evolution: ВМ, подсети, группы безопасности и сетевые интерфейсы.
Advanced: ВМ ECS, сети VPC, подсети, группы безопасности и привязки портов VPC.

Инвентарь выбранных типов собирается всегда. Дополнительно выбираются сетевые
подключения ВМ и правила групп безопасности. Набор доступных флажков меняется
при смене источника. Инвентарь может уже содержать основные сетевые параметры;
дополнительный флажок получает отдельный список интерфейсов.

### Evolution Compute (`https://compute.api.cloud.ru`)

| GET-путь | Данные |
| --- | --- |
| `/api/v1/projects/{project_id}` | Проверка доступа к проекту |
| `/api/v1/vms?project_id=...` | ВМ |
| `/api/v1/subnets?project_id=...` | Подсети |
| `/api/v1/interfaces?project_id=...` | Интерфейсы проекта |
| `/api/v1/interfaces?project_id=...&vm_ids=...` | Интерфейсы отдельной ВМ |
| `/api/v1/security-groups?project_id=...` | Группы безопасности |
| `/api/v1/security-groups/{id}/rules` | Правила группы безопасности |

Пагинация списков: `offset/limit`, размер страницы до 100, ответ `items/total`.
Проверяются общее число элементов и отсутствие повторов между страницами.
[REST API и актуальная OpenAPI-схема](https://cloud.ru/docs/virtual-machines/ug/topics/api-ref-v3).

### Advanced

| Сервис и GET-путь | Данные |
| --- | --- |
| ECS `/v2.1/{project_id}/servers/detail` | ВМ и проверка подключения |
| ECS `/v2.1/{project_id}/servers/{id}/os-interface` | Интерфейсы ВМ |
| VPC `/v1/{project_id}/vpcs` | Сети VPC |
| VPC `/v1/{project_id}/subnets` | Подсети |
| VPC `/v1/{project_id}/ports` | Порты и привязки групп безопасности при сборе интерфейсов |
| VPC `/v1/{project_id}/security-groups` | Группы безопасности |
| VPC `/v1/{project_id}/security-groups/{id}` | Правила группы безопасности |

Пагинация: `limit/marker`, до пустой страницы, с проверкой повторов. Подпись
проверена на синтетическом запросе сравнением с официальным SDK 2.0.4 из
[руководства Python Signing Guide](https://support.hc.cloud.ru/en-us/devg/apisign/api-sign-sdk-python.html).
Справочники [ECS/VPC](https://cloud.ru/docs/advanced/overview/advanced-en-api).

## Результаты и границы

История хранит платформу, параметры и состав запуска, ресурсы, ошибки и журнал
методов/адресов API без авторизационных заголовков. Доступны отмена, просмотр
ресурсов, ошибок и запросов, экспорт JSON. Ошибка отдельного типа данных даёт
частичный результат; она не заменяется пустым успешным ответом.

Проверка подключения подтверждает доступ к проекту (Evolution) или чтение
списка ECS (Advanced); права на остальные выбранные сервисы проверяются при
сканировании. Пустой проект может успешно пройти проверку.

Гостевые пароли, cloud-init, metadata и URL удалённых консолей не сохраняются.
Снимки включают имена и сетевые адреса ресурсов. TLS проверяется; редиректы
не выполняются. Облачная инфраструктура не изменяется.

Cloud Firewall, Network ACL, NAT Gateway, маршрутизация и внутренние настройки
гостевых NGFW в эти два коллектора пока не входят. Сбор конфигурации не запускает
локальные проверки качества правил и не подтверждает достижимость сети.

Для ручной сверки с матрицей 2.0.0 используются сохранённый сбор,
подтверждённые назначения интерфейса, направление и семейство адресов.
В Evolution доступны объявления одной группы или объединение разрешений
всех групп интерфейса. У Advanced рассматривается одна выбранная группа.
Когда сохранённый сбор полностью подтверждает единственное назначение,
включённую фильтрацию и состояние и приоритет всех применимых правил,
поддерживается локальный порядок для новых соединений по известным адресам
порта. Для остальных снимков сохраняется режим объявлений. Сохраняются идентификатор сбора, путь до
правила и контрольная сумма снимка. Для входящих соединений нескольких групп
Advanced требуется явное свидетельство об их последовательности. Оно связано
с точным интерфейсом, идентификатором и контрольной суммой сбора и тем же
моментом наблюдения. Все назначения, состояния и приоритеты правил должны быть
известны. Удалённые группы, действующие сеансы, маршруты и сквозной доступ
остаются отдельными источниками данных. Неизвестные условия и ошибки сбора
сохраняются в ограничениях.
Автотесты и самопроверка EXE используют синтетические ответы; реальный аккаунт
проверяется после заполнения подключения пользователем.
