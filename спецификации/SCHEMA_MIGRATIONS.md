# Изменения контрактов данных

## Общие сверки в отчёте запуска

Пакет `firewall-compliance.batch-report` 1.4.0 содержит
`matrix_scope_assessments` с идентификаторами и полными результатами общих
сверок и `matrix_scope_versions` с утверждёнными матрицами по контрольной
сумме. Версия включается один раз на пакет. HTML поддерживает прежние пакеты
без этих полей. Для исторических сверок в JSON сохраняется опциональный
`baseline_run_id`. Прежняя связь читается из сохранённой диагностики.
Запись остаётся неизменяемой. Схема SQLite сохранена.

## Компактные источники общей сверки матрицы

Источник коммутатора без правил может содержать поле
`revision_checksum_kind="stored_json"`. Контрольная сумма относится к JSON
точной сохранённой ревизии в элементе запуска. Такой источник используется
при разборе пути. Участие в назначении или оценке политики исключено моделью.
При открытии пути проверяются идентичность и контрольная сумма полного снимка.
При отсутствии поля используется прежняя каноническая контрольная сумма модели.
Формат DeviceRevision и схема SQLite сохранены. Для новых результатов
с компактными источниками нужен читатель, поддерживающий это поле.

## Логические сети и VLAN 0.13.0

Первая запись добавляет `logical_networks`, `logical_vlan_bindings` и
`logical_network_events` транзакционно. До первой записи реестр читает старую
базу как пустой каталог сетей. SQLite `user_version=1` и JSON ревизий сохраняются.
Сеть идентифицируется внутри проекта, привязка коммутатора использует
`project_id`, `device_id` и локальный VLAN ID. Полная SQLite-копия включает
ручные записи и историю.

## ArubaOS Controller 0.12.0

Необязательный `ParseResult.controller_inventory` имеет схему 1.0.0 и
проверяет принадлежность источнику по имени, SHA-256 и времени получения.
В `Service` добавлены необязательные номер IP-протокола, порты источника и ALG.
У прежних записей эти поля опускаются при сериализации. DeviceRevision и
SQLite DDL сохраняют версию. Старые строгие читатели могут потребовать
обновления для новых payload. Batch-report 1.3.0 включает `controller_import`.
Операционный просмотр `show ap active` не записывает данные в проект.

## Switch import 0.10.0

Необязательные ParseResult.switch_facts/switch_policies имеют схему 1.0.0;
Rule.policy_purpose опционален и отсутствует в legacy-сериализации. Чтение старой
ревизии не добавляет факты и не переписывает историю. SQLite DDL не меняется:
целые payload хранятся в JSON. Старые readers с extra=forbid не обязаны принимать
новые envelopes. Batch-report 1.2.0 добавляет switch_import. Точная совместимость
и влияние версий парсеров на diff описаны в DOCUMENTATION.md.

## История матрицы и сверок R4

Опциональные workspace_comparison_meta/version=1 и workspace_run_comparisons сохраняют неизменяемую историю сравнений. Запись содержит comparison_id, project_id, before_run_id/after_run_id с FK на запуски, saved_at, site_id, payload и SHA-256. Перед явной инициализацией создаётся полная резервная копия; DDL выполняется транзакционно, legacy user_version=1 не меняется. Чтение не создаёт таблицы; неизвестная/частичная схема и org_context отклоняются. UPDATE/DELETE запрещены триггерами. Оболочка firewall-compliance.run-comparison-artifact1.0 содержит полный пакет сравнения и сверяет ссылки, даты и область; отфильтрованный экспорт не сохраняется в эту историю. Пакет batch-report1.1 также содержит run_comparisons и run_comparison_notes.

Экспорт firewall-compliance.run-comparison1.0 содержит выбранные run IDs, даты, область площадки, зафиксированные параметры профилей, сопоставление устройств, независимые diff-каналы и ограничения. Режим full_comparison включает использованные нормализованные ревизии; режим view ограничивает строки фильтром и сохраняет только ссылки на ревизии соответствующих устройств, без полных входов и скрытого перечня исключённых ресурсов. Совпадение сигнатуры finding не является доказательством стабильной идентичности правила. Отсутствие finding после неполного анализа обозначается отдельно; статусы исходных findings не меняются.

Settings новых VMware analysis runs включают source_id, source_config_fingerprint, source_selection_fingerprint и source_collection_state, полученные из зафиксированного cloud_scan. Поля опциональны для чтения старых запусков; их отсутствие означает неподтверждённую область, а не совпадение с текущим подключением. Параметры профиля анализа не расширяются реквизитами подключения. Run-comparison отражает input_scopes и selection_basis; автоматический baseline допускается только при подтверждённой сопоставимости.

Опциональный workspace_matrix_meta/version=2 сопровождает workspace_matrix_versions и workspace_matrix_assessments. Ключ версии матрицы — project_id/version; payload, SHA-256 и время сохраняются отдельно. Ключ сверки — artifact_id; запись содержит project_id, matrix_version с составным FK на историю матрицы, revision_id, origin_run_id, подпись устройства, дату, payload и SHA-256. UPDATE/DELETE истории запрещены триггерами. Legacy user_version=1 не меняется. Чтение принимает отсутствие схемы и историю версии 1; создание/переход 1→2 выполняется только явной записью с полной резервной копией и одной транзакцией. Неизвестная/частичная схема или активированный org_context не перезаписываются.

MatrixAssessmentArtifact1.0 фиксирует AccessMatrix1.0, нормализованную DeviceRevision, MatrixAssessment1.0, параметры исходного профиля без подключений, версию приложения, область и ссылки на исходные run/item. Ссылки на запуск и элемент задаются вместе; при сохранении проверяются их проект и точное совпадение ревизии с сохранённым item. Оценки требований и evidence rule IDs должны относиться к вложенным входам. История открывается с проверкой checksum и метаданных без повторного анализа; листинг метаданных постраничный, полные входы читаются по выбранному ID.

AccessMatrix2.0 принимает необязательные цепочки со ссылками на обязательные
требования той же области. Пустой список опускается при записи. В MatrixAssessment2.0
отметка `attachment_limited` для локальной политики сохраняет ограничения
применимости к пути отдельно от полноты оценки ACL. Отсутствующее поле означает,
что такая дополнительная отметка в снимке не сохранена. Старые payload читаются
без перезаписи. JSON разбора цепочки и общей сверки области имеют собственные
версии 1.0.0 и ссылки на сохранённые источники. SQLite DDL не меняется.

Необязательная `zone_pair` с двумя именами зон сохраняется в требованиях и
ограничениях AccessMatrix2.0, результатах общей сверки и офлайн-наблюдениях.
При отсутствии поля сериализация сохраняет прежний вид. Материалы назначенных
наборов и ссылки на исключения сверяются с учётом выбранной пары.

История общей сверки добавляет опциональную таблицу
`workspace_matrix_scope_assessments` на первой записи после полной копии SQLite.
Ключ записи — UUID. Хранятся `project_id`, утверждённая версия матрицы,
`scope_id`, точный фильтр площадки, краткие счётчики, неизменяемый JSON и его
SHA-256. При записи проверяются матрица, исходные ревизии и ссылки на правила.
У источника из сохранённого запуска есть run/item. У облачного источника
сохраняются ID сбора и параметры проекции группы. Простой просмотр не создаёт
таблицу. Значения `PRAGMA user_version` и `workspace_matrix_meta` сохраняются.

`context_inputs` содержит основной офлайн-снимок, время оценки и назначения.
Необязательные `additional_contexts` хранят другие снимки той же области, каждый
со своим временем оценки. `context_id` назначения указывает снимок. При его
отсутствии используется основной снимок. Новые пустые поля пропускаются.
Итог сеанса связан с контрольной суммой выбранного снимка, утверждённым
требованием и сохранённым адресным составом. Для разбора пути считывается
конкретный run/item с проверкой контрольной суммы ревизии. Старые JSON и строки
SQLite читаются без миграции.

Необязательные `path_bindings` источника сохраняют подтверждённые префиксы для
разбора пути требований без однозначной политики. Эти префиксы хранятся отдельно
от `bindings`, использованных для расчёта покрытия. Пустое поле пропускается.

AccessMatrix2.0 может содержать `boundary_groups` со ссылками на отдельные
закрытые области и необязательными подписями точек `point_names`. Состав групп
входит в контрольную сумму утверждённой матрицы. Отсутствующие поля опускаются
из JSON. SQLite хранит прежние атомарные строки, а сводка вычисляется из
зафиксированной версии. При экспорте сгруппированного результата контейнер
`arxion-matrix-scope-v1` включает матрицу и исходную сверку. При чтении проверяются
контрольная сумма и точный состав строк. Прежние файлы сверок читаются напрямую.

Офлайн-наблюдения цепочки 1.0.0 включают необязательные `observations` и
`transactions`. Они привязаны к контрольной сумме матрицы. Отчёт раздельно хранит
конфигурационные выводы, записи попыток и сопоставленные транзакции. Старые
входы без наблюдений или транзакций читаются без миграции.

JSON разбора по общей сверке добавляет `scope_assessment` со ссылкой на запись
истории, временем, состоянием и контрольными суммами результата и версии матрицы.
Для каждого участка сохраняются тип назначения источника и идентификатор
ревизии при её наличии. Новые поля пропускаются в отчётах по отдельным сверкам.

В `switch_policies` объявления Comware могут содержать `match_order`, а
подтверждённая входящая VLAN-привязка содержит `configured_profile`. Поля
отсутствуют в JSON, если основание неизвестно. Снимки старых версий читаются
без изменений. Ранее выбранный ID объявления `acl:N` остаётся доступен при
новом импорте вместе с отдельным ID привязанной политики.

Облачная проекция `sg-1.2.0` сохраняет отдельное свидетельство порядка
назначений Advanced. В `cloud_selection` оно опционально и опускается для
прежних проекций. Контрольная сумма исходного сбора и контрольная сумма порядка
сохраняются отдельно. Порядок влияет на идентификатор ревизии, а ключи
устройства и политики остаются стабильными между снимками.

Источник общей сверки VMware может содержать `vmware_origin` с полями `scan_id`,
`record_index` и `resource_id`. Индекс относится к исходному массиву ресурсов
сохранённого сбора. Для этого источника также сохраняется `imported_at`.
При восстановлении проверяются проект, сохранённая площадка, точная запись,
идентификатор Edge и контрольная сумма нормализованной ревизии. Для прежних
источников поле отсутствует. SQLite DDL и контейнер экспорта сохраняются.
Строка может получить маршрутизацию `incomplete_policy_sources`, если доступен
один кандидат, а данные другого известного источника той же политики отсутствуют.
Сохранённый кандидат доступен для явного выбора. Строгим внешним читателям нужна
поддержка дополнительного значения и поля происхождения VMware.

Метаданные карточки ресурса могут содержать `matrix_source_bindings`. Каждая
запись хранит подтверждённые префиксы и точный ключ из `site_id`, `device_id`,
`platform`, `device_context`. Пустой контекст устройства хранится как `null`.
Прежнее поле `matrix_address_binding` читается в стандартном контексте площадки.
При нескольких допустимых площадках источника несовпадающие префиксы одной
карточки остаются неопределёнными. Сохранённые сверки используют прежний формат
для записи применённых префиксов. SQLite DDL сохраняется.

`matrix_source_bindings` и `MatrixCatalogBinding` могут дополнительно содержать
`vrf`. Общая сверка сохраняет `policy_vrf` в строке с подтверждённой VLAN-привязкой.
При восстановлении источника VRF сверяется с сохранённой ревизией. В AOS-CX новые
ревизии могут содержать `SwitchInterface.vrf_source_location` для явной команды
привязки интерфейса VLAN. Отсутствующие поля опускаются из JSON. Старые снимки и
сверки читаются с прежним составом, SQLite DDL сохраняется. Переносимый черновик
содержит только адресные привязки без VRF.

При явном объединении ресурсов сохранённый `merged_into` используется для
разрешения прежнего ID карточки в новой сверке. Используется только активная
итоговая карточка того же проекта. Артефакты сохраняют исходный ID ссылки и
префиксы, использованные в конкретной сверке. Форматы матрицы и SQLite прежние.

Пакет firewall-compliance.batch-report1.1 добавляет generated_at, selection, matrix_assessments и matrix_assessment_notes. Сверки включаются только по сохранённой связи с выбранным запуском; ошибки чтения/целостности обозначаются, а не заменяются новой оценкой. Режим full_run явно исключает текущие фильтры UI. HTML-renderer продолжает принимать пакеты 1.0 с отсутствующими новыми полями. Внешним строгим JSON-readers нужна поддержка версии 1.1. Версии AnalysisResult, AclMap и DeviceRevision этим изменением не повышаются.

## Проекции карт R3, 2026-11-01

Приложение 0.8.0 сохраняет необязательный map_view_settings в существующем project.settings JSON: node_limit, line_limit и layouts. Layouts — ограниченный кэш стабильных слотов узлов по виду/зоне; повреждённые записи пропускаются, отсутствие кэша означает стандартную раскладку. Схема SQLite и доменные JSON AnalysisResult/AclMap/DeviceRevision не меняются. Область облачного источника дополнительно различает явно заданные ECS/VPC endpoints; старые подписи зон сохраняются отдельно и не переносятся по совпадению IP/имени.

ProjectMap — неперсистентная UI-проекция. Она содержит структурную принадлежность интерфейсов/сегментов, VDC и явных облачных ссылок, сохраняет исходные RuleEvidence и ссылки на нормализованные Rule для фильтров. Облачные URN/href/UUID сопоставляются только внутри типа, подключения и одного сбора. Неизвестная цель ссылки/локальная сеть ВМ обозначается явно и не становится общим адресным пространством. Визуальные группы и линии не добавляют доказательств reachability. Оригинальная AclMap остаётся гиперграфом с одной relation на правило.

## Завершение реализации R2, 2026-11-01

Приложение 0.7.0 добавляет opt-in workspace_source_sites_meta/version=1 и workspace_source_sites (ключ origin_project_id/source_key/site_id). Перед DDL создаётся отдельная полная резервная копия; миграция транзакционна, legacy user_version=1 не меняется. Таблицы связывают существующие integrations с workspace_sites, допускают несколько площадок и удаляют только текущие назначения при удалении подключения (ON DELETE CASCADE). Чтение не инициализирует схему. История runs/marks и исходные ревизии не переписываются; будущая активация org_context требует явного переноса метаданных.

Settings новых запусков могут содержать workspace_input_sites и source_site_ids как снимок заявленной области. В профиле допустимы rule_count_drop_percent/inventory_count_drop_percent; отсутствие полей в старом JSON не меняет старый fingerprint при чтении. Элементы запуска имеют необязательные collection_warnings и диагностику COLLECTION_COUNT_DROP; исходный AnalysisResult/DeviceRevision остаётся прежней версии. В cloud_scans.result добавлена необязательная integrity_warnings с причинами сравнения счётчиков. Эти предупреждения не меняют семантику findings/полноты и не являются доказательствами удаления. Старые readers, игнорирующие дополнительные поля SQLite JSON, сохраняют совместимость; строгим внешним читателям нового внутреннего payload требуется поддержка этих дополнительных полей.

## Основа рабочего пространства R1, 2026-11-01

Версия приложения 0.5.0. Legacy SQLite user_version=1 сохраняется. При явном действии пользователя добавляются workspace_metadata/schema_version=1, workspace_sites и workspace_device_sites; отдельно workspace_profile_history_meta/version=1 и append-only workspace_profile_history. Каждая инициализация перед DDL создаёт резервную копию полным SQLite backup, затем применяет DDL транзакционно. Инициализация не вызывается при простом открытии диалога или чтении. Неизвестные версии метаданных отклоняются. Конструкторы не активируют org_context.

Назначение площадки имеет ключ (origin_project_id, device_id), не меняет исходную ревизию и может быть снято. Проект не считается физической площадкой. История профилей сохраняет только параметры анализа; версия и SHA-256 canonical JSON фиксируются в settings нового run при включённой истории в одной транзакции с созданием run. Параметры подключения и секреты в профиль не входят. Исторические run/settings/marks не переписываются.

Перед будущей активацией org_context требуется явное перенесение этих таблиц в организационный контракт. При наличии org_context legacy writer отказывает; автоматическая конверсия старых projects в sites отсутствует. Откат — восстановление резервной копии при закрытом приложении. Поле текущего назначения площадки используется только в проекции просмотра и не объявляется историческим фактом размещения.

Публичные AnalysisResult, AclMap и DeviceRevision не меняют schema_version. Новый адресный индекс проектной карты является проекцией: ключ включает контекст и снимок; новые локальные контексты не равны старому default. Старые сохранённые пользовательские подписи адресных групп сохраняются в настройках и требуют явного сопоставления с новой группировкой. Порядок и смысл ACL при этом не изменяются.

## Общие результаты и архив ACL, 2026-10-28

AnalysisResult1.0 хранится отдельно в immutable checksummed analysis_results,
AclMap1.0 — в отдельной immutable acl_maps с project/run/item provenance.
SQLite user_version1 и существующие payload не переписываются. Проекции и
