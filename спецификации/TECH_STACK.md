# Технический стек

## Статус

Базовый стек утверждён для нового продукта и целевого MVP. Он будет пересмотрен после получения архитектурных и кибербезопасностных требований. Новая технология добавляется только при доказанной необходимости и с фиксацией решения в `DECISIONS.md`. Таблица ниже описывает выбор технологий, а не факт реализации всех компонентов.

## Принцип выбора

Продукт строится как модульный монолит с локальной обработкой по умолчанию. Приоритеты: точность анализа, воспроизводимость, безопасность данных и низкая операционная сложность для одиночной разработки.

Первичная среда поставки - Windows 10/11 x64 на рабочем ПК пользователя. Детали закреплены в `DEPLOYMENT_TARGETS.md`.

| Область | Технология | Назначение |

## Фактически используется (31.10.2026)

- Python, Pydantic v2 и Typer: модели, parser adapter, проверки и CLI с JSON в stdout.
- `uv`, `uv.lock`, Ruff, mypy и pytest: локальные проверки и зафиксированные зависимости. Hypothesis и pytest-cov входят в dev-зависимости; наличие пакета не доказывает полноту соответствующих проверок.
- Pydantic Settings и structlog установлены как базовые зависимости, но не образуют готовую систему конфигурации и аудита в текущем сценарии анализа.
- NetworkX, Jinja2, SQLAlchemy и Alembic объявлены в optional extras. Qt desktop использует stdlib SQLite и автономный HTML без этих extras; графовый анализ и ORM-миграции пока не реализованы.
- Git и GitHub Actions подключены. Windows workflow раздельно выполняет quality/test/smoke/package/security и карты/архитектуру; см. CURRENT_STATE.md для привязанной к коммиту сводки.
- PySide6 установлен для основного desktop; PyInstaller используется для Windows portable сборки. FastAPI, web UI, PostgreSQL, dependency scan и SBOM остаются целевыми компонентами или отдельными релизными проверками.

## Очереди и фоновые задачи

До появления подтверждённой серверной нагрузки внешний брокер не используется.
Desktop UI имеет внутреннюю очередь заданий и один Python worker (ADR-016), без Redis.
Для длительных анализов в серверной версии допускается `RQ` с Redis.
Введение Kafka, RabbitMQ или другого брокера требует ADR.

## Намеренно не используем в MVP

- Микросервисы и Kubernetes.
- Облачное хранилище или внешние API по умолчанию.
- Kafka, RabbitMQ, Elasticsearch.
- Полноценный Web UI до стабилизации CLI, доменной модели и API.
- Автоматическое изменение конфигураций устройств.

## Целевой минимальный контур поставки

```text
CLI -> application services -> domain/analysis/parsers -> SQLite -> JSON/CSV/HTML reports
```

Для этого сценария Docker не является обязательной зависимостью пользователя: он применяется для воспроизводимых сборок и поздней серверной поставки.

Текущий CLI-контур: чтение локального файла -> общий catalog ASA/HP-Aruba/Comware/UserGate/Ideco -> ревизия в памяти ->
Firewall Assurance -> JSON в stdout. Desktop добавляет согласованную сессию, очередь
в worker, просмотр результатов и сохранение исходного JSON. Сетевой импорт, query и
forwarding вызываются отдельными сценариями. Desktop сохраняет policy-проекты в SQLite и экспортирует HTML/JSON-пакет; CSV доступен в общем AnalysisResult.

Целевой server deployment развивается позднее:

```text
CLI / Web UI / REST API -> FastAPI -> domain and analysis -> PostgreSQL
                                           |
                                      optional Redis worker
```

## Требования к выпуску

- Версии приложения, парсера, каталога checks и схемы отчёта записываются в результат анализа.
- Автоматические проверки выполняются в GitHub Actions. Локальные проверки и сборки требуют прямого запроса пользователя согласно AGENTS.md. Коммерческая готовность требует проверенной воспроизводимости релизного артефакта.
- Если выпускается Docker image, он не содержит тестовых конфигураций, результатов анализов и секретов.
- Для подготовки v1.0 состав подтверждений определяется отдельно; генерация SBOM пока не подтверждена. CI выполняет существующие тесты, линтинг, type checks и dependency scan. Image scan обязателен только при выпуске контейнерного образа; Windows-поставка проверяется отдельно без требования Docker.
