# FR-011: проверки заданных условий сервисного доступа

Реализованы два дополнительных `PolicyCheck` в `checks/access/`;
`analysis/policy_exposure.py` сохраняется как совместимый путь импорта:

- `DangerousServicesCheck(profile)` — `FW-DANGEROUS-SERVICES`;
- `UntrustedAdministrativeAccessCheck(profile)` — `FW-ADMIN-UNTRUSTED`.

Они совместимы с `PolicyCheckContext` и возвращают обычный `CheckResult`.
Проверки подключены к CLI (`--extended-policy-checks`, `--policy-exposure-profile`),
настройкам Qt и анализу VMware. Они используют явно заданный профиль; существующие
семь проверок не заменяются и не переоцениваются при чтении отчётов.

## Явный организационный профиль

`domain/policy_exposure.py:PolicyExposureProfile` имеет собственную схему `1.0.0`.
Для сохранения используются `model_dump(mode="json")` / `model_dump_json()`, для
чтения — `model_validate()` / `model_validate_json()`. Неизвестные поля и версии
отвергаются. Проверка создаёт отдельный глубокий снимок профиля: изменение исходного
объекта после создания проверки не меняет её результат.

| Поле | Смысл |
| --- | --- |
| `profile_id`, `version` | Идентичность и версия требований организации |
| `dangerous_services` | Явный каталог сервисов, запрещённых организацией |
| `administrative_services` | Явный каталог административных сервисов |
| `administrative_targets` | CIDR ресурсов, объявленных административными целями |
| `trusted_admin_networks` | CIDR источников, которым организация доверяет административный доступ |

В каждом каталоге используются `PolicyServiceSelector`: уникальные `selector_id`,
название `name`, протокол `tcp`, `udp` или `icmp`. TCP/UDP требуют явно указанных
`port_ranges: [{start, end}, ...]`; ICMP не допускает порты. Границы включительны,
TCP/UDP-порты находятся в диапазоне 1–65535. CIDR нормализуются, дубликаты сетей
удаляются; DNS, имена зон и строка `any` не считаются CIDR. Универсальную сеть можно
указать явно как `0.0.0.0/0` или `::/0`.

`None` означает отсутствие организационного требования, а не разрешение всех сетей.
Для соответствующей проверки это `partial` с `EXPOSURE_POLICY_UNKNOWN` и
`CHECK_NOT_EXECUTED`. Пустой каталог или пустой список административных целей
означает явно отключённую область и возвращает `not_applicable`. Пустой список
доверенных сетей означает, что организация не доверяет ни одному источнику.
Частные адреса автоматически доверенными не становятся.

Пример профиля, заданного организацией:

```json
{
  "schema_version": "1.0.0",
  "profile_id": "synthetic-example",
  "version": "1",
  "dangerous_services": [
    {"selector_id": "org-service", "name": "Запрещённый организацией сервис",
     "protocol": "tcp", "port_ranges": [{"start": 23, "end": 23}]}
  ],
  "administrative_services": [
    {"selector_id": "admin-service", "name": "Объявленный административный сервис",
     "protocol": "tcp", "port_ranges": [{"start": 22, "end": 22}]}
  ],
  "administrative_targets": ["192.0.2.0/24"],
  "trusted_admin_networks": ["198.51.100.0/25"]
}
```

Этот пример не является встроенной политикой безопасности или классификацией
любого TCP/22, TCP/23 либо TCP/443: назначение сервисов определяет организация.
Без явных административных целей и доверенных источников вывод об административном
доступе не формируется.

## Семантика проверки

Область — заданные условия активного нормализованного `ALLOW`. `DENY`, `DROP`,
`REJECT`, `LOG` и отключённые правила не считаются разрешениями. Неизвестное
действие или неразрешённое условие порождает ограничение и не превращается в `ANY`.
Для проверки сервисов вычисляется пересечение протокола и destination ports
правила с явным селектором. Известный сервис `ip` включает явный протокол селектора.

Для административного доступа дополнительно вычисляются:

1. Пересечение назначения правила с административными целями.
2. Разность источника правила и объединения доверенных сетей.
3. Непустое пересечение сервисов с административным каталогом.

IPv4 и IPv6 обрабатываются раздельно; источник одной семьи и цель другой не создают
связь. Доверенные CIDR рассматриваются объединением, а не по одному: два соседних
доверенных `/25` полностью покрывают соответствующий `/24`. В доказательстве
сохраняются точные включительные интервалы источника, назначения и портов.

Это обзор заданных условий, такой же по уровню интерпретации, как существующий
any-any check. Предыдущее `DENY` не удаляет сам факт наличия последующего заданного
`ALLOW`; находка не утверждает, что такое правило эффективно срабатывает.
First-match порядок, NAT, маршруты и runtime не вычисляются. Неизвестное
логирование не делает известные адреса/порты неизвестными; состояние логирования
сохраняется в исходном нормализованном правиле доказательства.

## Полнота, доказательства и лимиты

Findings содержат `configuration_id`, `revision_id`, `device_id`, ID правила,
его `SourceLocation`, исходное нормализованное правило, ID/версию/SHA-256 профиля,
селектор и точные пересечения. ID finding детерминирован для той же ревизии,
проверки, профиля, правила и селектора. При изменении профиля прежняя находка не
выдаётся за результат новых требований.

Критичность — `medium` для организационно запрещённого сервиса и `high` для
заданного административного доступа вне доверенных сетей. Это приоритет проверки
политики, а не подтверждённая уязвимость сервиса или вероятность эксплуатации.

Ограничения разбора сохраняются как `INCOMPLETE_PARSE`; пригодные правила могут
давать находки в частичном результате. Если не проверено ни одного пригодного
разрешения и есть ограничения, добавляется `CHECK_NOT_EXECUTED`. Пустое множество
находок не доказывает безопасность всей конфигурации.

Каждый check имеет `max_operations` (по умолчанию 100000, допустимо 1–10000000).
Сканирование правил, сравнения селекторов и интервальная арифметика расходуют
общий бюджет. При исчерпании сохраняются уже полученные результаты и
`EXPOSURE_LIMIT_REACHED`, итог не может быть `complete`. Размеры профиля ограничены:
256 селекторов на каталог, 128 диапазонов на селектор, 4096 CIDR на список.

Проверки чистые: не выполняют I/O, DNS, API-запросы и не меняют ревизию.
Существующие схемы отчётов, SQLite и parser/check versions ими не переписываются.

## Подтверждение

`tests/regression/test_policy_exposure.py` проверяет неизвестный и пустой профиль,
неподдержанные условия, действия, протоколы, IPv4/IPv6, объединение и вычитание
доверенных сетей, точность источников и портов, бюджеты, неизменяемый профиль,
повторяемые ID и JSON round-trip. Два Hypothesis-теста сопоставляют результаты
с независимыми конечными множествами адресов/портов. Только синтетические данные.
