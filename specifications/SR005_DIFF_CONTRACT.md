# SR-005: сравнение ревизий и доказательства различий

Статус: реализация контракта, 2026-10-27. Область — записанные Interface,
Route, NetworkSegment и TopologyLink. Эффективные разрешения, policy/NAT/object
diff, причинность изменений на устройстве и перенос пользовательских решений
между запусками в этот контракт не входят.

## API и совместимость

Публичный API сохраняется:

```python
compare_device_revisions(before: DeviceRevision, after: DeviceRevision) -> DeviceRevisionDiff
```

DeviceRevision остаётся 2.0.0; SQLite, parser/check versions и отчёты Firewall
Assurance не меняются. Новые результаты DeviceRevisionDiff содержат
`schema_version="2.0.0"`. Новые поля добавлены к существующему классу результата;
`changes`, `normalization_changed`, ссылки на ревизии и `limitations` сохранены.

| Поле | Семантика новых результатов |
| --- | --- |
| `changes` | Различия известных сетевых значений: added/removed/modified |
| `provenance_changes` | Источники, UUID документов, source mapping, времена, основания наблюдения и исходные байты |
| `normalization_changes` | Смена parser_version и различия, причинность которых при этой смене не установлена |
| `completeness_changes` | Достоверность полей/наборов, полнота, сравнимость scope, первое наблюдение и отсутствие в новом снимке без доказанного удаления |

Каждый элемент трёх новых разделов — RevisionComparisonDetail с entity_kind,
entity_id, code, changed_fields и Evidence. Полные исходные значения фактов и
source locations сохраняются в Evidence, даже когда различие не включается
в `changes`. При added/removed сохраняются также обе inventory-проекции.
Коды проверяются относительно раздела; normalization_changed согласуется с
normalization_changes. Результат публикует глубокий неизменяемый snapshot.
Копирование через model_copy также повторяет проверку схемы и разделов.

Прежний JSON не имел версии. Отсутствие schema_version читается как прежнее
структурное сравнение: старые changes и normalization_changed сохраняются без
переклассификации. Новые разделы и schema_version при повторной сериализации
такого результата не добавляются. Нельзя добавить классифицированные разделы
к unversioned результату. Неизвестные версии отклоняются. Новый JSON требует
обновлённого читателя; совместимость со старым строгим читателем не заявляется.
Исторические результаты не пересчитываются при чтении, golden-файлы не обновляются.

SHA-256 конфигурации учитывается в provenance_changes. Изменение исходных байтов
без отличий сетевых фактов больше не создаёт CONFIGURATION modified в changes.
Это намеренное уточнение нового контракта, а не изменение прежнего JSON.

## Известные значения

Сравниваются только перечисленные доменные значения, без происхождения и времени:

| Сущность | Значения |
| --- | --- |
| Interface | name, addresses, zone, enabled |
| Route | destination, next_hop, outgoing_interface_id, metric, administrative_distance, route_kind, table_id, is_blackhole |
| NetworkSegment | name, cidrs, zone |
| TopologyLink | left_endpoint_id, right_endpoint_id |

Нужно data_status=known с обеих сторон. Неизвестные enabled/zone,
metric/administrative_distance и route_kind=unknown не превращаются в известные
отсутствующие значения. Для addresses нужны addresses_status known/absent;
неизвестные адреса остаются в completeness_changes. Пустые cidrs сегмента
консервативно считаются недоступным значением: модель не доказывает известную
пустоту этого поля. Порядок addresses/cidrs не меняет семантику набора.

Известные поля одного факта можно сравнить при неполном перечислении остальных
фактов. Недоступность поля и отсутствие факта — разные ситуации. Изменение
достоверности фиксируется отдельно, даже если сами значения совпадают.

При смене parser_version известные различия сохраняются как
normalization_dependent, а не попадают в changes. Это консервативное правило
применяется и при одновременной смене исходных байтов: причина различий не
установлена. Истинное изменение устройства из версии парсера не выводится.
Сравнивается сохранённая Configuration.parser_version. Отдельные версии сетевых
адаптеров в DeviceRevision не записаны; контракт не восстанавливает их по UUID
документа и не заявляет неизвестную историю нормализации.

## Отсутствие и сравнимость

REMOVED допускается, только если в первом снимке есть известный факт и время
наблюдения, а второй снимок имеет observed_at, полный CollectionEvidence,
status known/absent и сравнимый scope. ADDED требует симметричного доказанного
отсутствия в первом снимке и известного наблюдаемого факта во втором.
NOT_APPLICABLE не считается доказательством удаления. Даже допустимые
added/removed описывают различие записанных наблюдений в заявленной области;
они не доказывают реальную операцию изменения устройства.

При недостатке доказательств выдаются not_observed/first_observed и, при
необходимости, scope_incomparable. Неполнота не скрывает исходные значения и
не создаёт removed/added. Изменение статуса набора видно само по себе, даже
если оба списка фактов пусты.

Device ID, vendor/platform и device context должны совпадать. Configured routes
и routing_table не смешиваются. CollectionEvidence не содержит отдельной
размерности IP family/table: проверка отсутствия и сопоставимости маршрутов
ограничена записанными IPv4/default фактами. IPv6 и иные таблицы остаются
scope_incomparable; VRF и расширенное покрытие не выводятся из имени устройства.

Идентичность сопоставляется по ID. ASA route_id включает UUID документа и
номер строки, поэтому оставшиеся маршруты одной сравнимой области дополнительно
сопоставляются по точно равным сетевым значениям как мультимножество. Кратность
сохраняется. Отличающиеся значения или неоднозначные изменённые маршруты не
получают выдуманную идентичность. Смена ID равных маршрутов видна в provenance.

## Потребители и проверка

Desktop backend.compare_sessions/compare_revisions сохраняют возвращаемый тип.
Legacy live_app показывает и экспортирует полный model_dump_json, поэтому новые
разделы доступны без потери сведений. Новому потребителю нельзя оценивать все
различия только по len(changes): отсутствие сетевых изменений не означает
равенство полноты или происхождения.

Qt compare_selected_runs сравнивает сигнатуры findings и не вызывает этот API.
ProjectStore не хранит отдельный structural diff. Этот срез не меняет эти
механизмы и не превращает finding diff в сетевой diff.

Синтетические регрессии: harness/tests/test_revision_diff_semantics.py —
provenance-only импорт, incomplete disappearance, полное наблюдаемое отсутствие,
known/unknown поля, четыре семейства фактов, parser change, изменение SHA-256,
маршруты с новыми ID и дубликатами, scope/context, прежнее чтение, детерминированная
сериализация и неизменяемость. Для реализации нужны Ruff, mypy, эти тесты,
регрессии downstream и полный harness gate. Исторические отсутствующие
tests/fixtures не заменяются обновлением goldens.
