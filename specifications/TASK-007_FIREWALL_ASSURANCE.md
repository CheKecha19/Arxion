# TASK-007: Firewall Assurance

Приоритет: P0
Статус: Готово
Дата завершения: 2026-10-09

## Цель

Выполнить семь независимых проверок нормализованной политики одной ревизии и получить воспроизводимые findings с Evidence и явными ограничениями достоверности.

## Контекст

Фаза 7 ROADMAP, FR-012 и FR-031, ARCHITECTURE, DOMAIN_MODEL, DEVELOPMENT_RULES, ADR-003 и ADR-007.

## Область задачи

- Общий контракт независимой проверки и результат каталога Firewall Assurance.
- Any-any, дубликаты, полное затенение одним предыдущим правилом, кандидаты на объединение, логирование, описания и отключённые правила.
- Нормализация явных адресных CIDR/диапазонов и destination ports для сравнения условий.
- Явные область, направление и first-match семантика политики; полный разбор условий правила.
- Сценарий SourceDocument -> ParserRegistry -> DeviceRevision -> Firewall Assurance и локальная команда CLI.
- Консервативная обработка ограничений Cisco ASA, влияющих на достоверность checks.

## Вне области задачи

Reachability, NAT-семантика, DNS/FQDN resolution, частичное затенение, затенение объединением нескольких правил, автоматическое изменение конфигурации, жизненный цикл finding в БД и общий AnalysisResult Фазы 9.

## Критерии приёмки

- Finding содержит revision_id, configuration_id, связанные правила, source mapping, Evidence и рекомендацию.
- Unknown/unsupported условия порождают диагностику неполноты; пустой список findings не заявляет безопасность политики.
- Попарные проверки работают только внутри одной явно определённой first-match области и при полном разборе источника; неоднозначный порядок и превышение лимита объясняются.
- Дубликат имеет одинаковые условия, действие и известную настройку логирования. Кандидат на объединение отличается ровно одной осью и сохраняет остальные условия и метаданные.
- При сравнении учитываются только общие для источника и назначения семейства адресов. Any и явная сеть /0 эквивалентны в соответствующем адресном семействе.
- Shadow finding указывает первое полностью покрывающее терминальное правило. Если это точный дубликат с тем же эффектом, достаточно duplicate finding. Структурный дубликат за более ранним блокирующим правилом может иметь обе независимые категории.
- Затенённые пары исключаются из кандидатов на объединение.
- Логирование требуется для активных разрешающих правил, описания - для активных правил; оба требования явно отключаются пользователем.
- Any-any означает активное разрешение между любыми адресами для указанного известного сервиса; вывод не утверждает фактическую достижимость.
- Каталог фиксирует версии схемы, приложения, парсера и checks; результат воспроизводим при неизменных входах.

## Проверка

- Unit tests: условия, CIDR, интервалы, протоколы, порядок, области, неполнота, preferences и детерминизм.
- Property tests: включение нормализованных интервалов сравнивается с независимым дискретным oracle.
- Integration/golden tests: реальный Cisco ASA synthetic export и CLI; эталоны обновляются только явной командой.

## Безопасность и обработка данных

Используются специально созданные synthetic fixtures. Обработка выполняется в памяти без сети. CLI выводит запрошенный технический результат в stdout; конфигурационные данные не пишутся в диагностические логи.

## Зависимости и риски

TASK-005, TASK-006. Неполный парсер может расширить условия, поэтому непонятые ACL, группы и сервисы должны давать диагностику. До реальных конфигураций требуется сопоставление обязательных требований ИБ.

## Запись о завершении

Реализованы `PolicyCheck`, `PolicyCheckContext`, семь независимых checks, `CheckResult` и `FirewallAssuranceResult`. Анализ использует только каноническую модель, сохраняет диагностические ограничения и не изменяет ревизию. Finding получает воспроизводимый UUID, связанный с ревизией, проверкой и правилами.

Добавлены application service `analyze_source()` и команда `firewall-compliance analyze`. Настройки требований логирования/описания и лимит попарного анализа сохраняются с результатом. Ограничения CLI: один файл, JSON в stdout; постоянное хранилище и общие exporters относятся к Фазе 9.

Cisco ASA adapter обновлён до `0.2.0`: явные ACL/direction/first-match, полный разбор поддержанных условий, `remark`, `inactive`, `log disable`, forward references к объектам, диагностика malformed/unsupported конструкций. Расширение не меняет экспериментальный статус платформы.

Проверка: Ruff format/check и mypy успешны; pytest - 214 passed. Есть независимая агентская проверка семантики и регрессионные тесты для найденных замечаний, property test с дискретным oracle, два новых golden-результата и CLI integration tests. Прежние значения fixtures сохранены, кроме документированного добавления полей и версии парсера; legacy baseline неизменен.

Обновлены ADR-008, DOMAIN_MODEL, SCHEMA_MIGRATIONS, SUPPORTED_PLATFORMS, ROADMAP, BACKLOG, CURRENT_STATE, SPECIFICATION_INDEX и README.

Пути, NAT-семантика и матрицы доступа развиваются следующими срезами.
