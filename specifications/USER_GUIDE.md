# Руководство пользователя: Firewall Compliance Qt

## Чтение результата R1 — 16.10.2026

В «Инфраструктуре» выберите устройство: карточка содержит сведения, правила, объекты, проблемы, историю и источники. В таблице проверок число найденного отделено от охвата; частичный разбор не означает отсутствие проблем. Одинаковые причины в одной области сгруппированы, исходные сообщения и доказательства остаются доступны. Полный технический просмотр показывает подробности правила/объекта. При изменённом исходном файле SHA-256 guard запрещает показывать его как прежнее доказательство. HTML использует те же группы; JSON сохраняет исходную структуру.

UserGate, Ideco и PT NGFW видимы как запланированные возможности; это не подтверждение поддержки их анализа. При 150% используйте прокрутку карточки и стрелки вкладок. Проверенная R1 portable поставка находится в `dist/ArubaUpdate/FirewallCompliance`; переносится вся папка с `_internal`. Результаты проверки и ограничения приведены в CURRENT_STATE.


Актуально на 14.10.2026. Приложение локально анализирует конфигурации, сохраняет
проекты и историю, показывает находки с доказательствами и формирует HTML/JSON.
Локальный анализ работает с файлами. Cloud.ru подключается явно для чтения через API; конфигурации не изменяются.

## 1. Запуск

Для portable-поставки распакуйте `dist\FirewallCompliance-windows-x64.zip` (примерно 54 MiB), затем откройте `FirewallCompliance.exe` в распакованной папке
`dist\FirewallCompliance`. Переносите всю папку, включая `_internal`; Python/uv
для такого запуска не нужны. Рабочие данные создаются в профиле пользователя.
Испытание сборки на текущем ПК не подтверждает чистые Windows 10/11 — результаты
проверки поставки перечислены в [CURRENT_STATE](CURRENT_STATE.md).

Для запуска из исходников нужны Windows 10/11 x64, Python 3.12+ и `uv`:

```powershell
uv sync --all-groups
.\.venv\Scripts\python.exe -m firewall_compliance.interfaces.desktop
```

Либо дважды щёлкните `Start-Desktop.cmd`. Он использует существующую `.venv` и
не устанавливает зависимости. Откроется тёмное окно Qt. Размер подстраивается
под доступный экран; таблицы и подробности имеют прокрутку, разделитель панелей
можно перетаскивать. Tab перемещает фокус; фокус выделяется голубой рамкой.

### Навигация

В боковом меню пять основных разделов:

| Раздел | Назначение |
|---|---|
| Обзор | Инфраструктура проекта, свежесть данных, последняя проверка и последние операции |
| Инфраструктура | Общий инвентарь устройств и облачных ресурсов, карточки и фильтры |
| Анализ | Проблемы, правила и объекты, расширенные инструменты |
| Операции | История, файлы и проверки, облачный сбор |
| Отчёты | Явный выбор запуска и экспорт HTML/JSON |

Настройки закреплены внизу. В общей шапке — проект, «Добавить данные» и
«Запустить проверку» (переход к подготовке файлов). Над страницей указан контекст:
проект, выбранная проверка или последние снимки. «Назад» / Alt+Left возвращает
выбор, фильтры и запуск; смена проекта очищает историю переходов.
Карта ACL остаётся следующим этапом и не занимает основной раздел меню.

## 2. Первый анализ: проект → папка → результат

1. Нажмите «Новый проект» и укажите понятное имя сети/площадки. В дальнейшем
   выбирайте проект в верхнем списке: история и настройки хранятся отдельно.
2. Нажмите «Добавить данные» → «Файлы конфигураций / папка». Нажмите «Добавить папку» для пакета конфигураций либо «Добавить файлы» для
   отдельных файлов. Предварительное определение формата идёт в фоне.
3. В «Операции → Файлы и проверки» проверьте имена файлов, формат, предлагаемый ID устройства и
   предупреждения. Двойной щелчок по строке позволяет подтвердить/изменить ID.
4. Если несколько файлов предложены как одно устройство, явно подтвердите связь.
   Один ID объединяет ревизии устройства; он не заставляет парсер принимать формат.
5. Нажмите «Запустить проверку файлов». Все семь реализованных проверок включены по умолчанию.
   Параметры логирования/комментариев и выбор проверок сохраняются в проекте.
6. Дождитесь уведомления о завершении: текущая страница остаётся открытой.
   Кнопка «Открыть результат» ведёт к проблемам завершившейся проверки. Ошибка отдельного
   файла не прерывает остальные и отражается в итогах. Откройте
   «Анализ → Проблемы» для разбора или «Отчёты» для сохранения результата.

Для первого знакомства используйте синтетический
`tests/fixtures/assurance/policy_quality.cfg`: при стандартных настройках ожидаются
семь проверок и 14 находок. Реальные файлы из вашей папки не копируются в fixtures.

### Какие конфигурации принимаются

| Формат | Граница |
|---|---|
| Cisco ASA 9.16 | Ограниченные ACL/objects/groups и policy checks |
| HP/Aruba AOS-Switch | Ограниченные IPv4 standard/extended/numbered ACL и явные bindings; authorized-managers отдельно |
| Aruba AOS-CX | Ограниченные IPv4 access-list ip и bindings; control-plane отдельно |
| HP/H3C Comware | Ограниченные IPv4 ACL/rules; SNMP ACL — управление устройством |
| ArubaOS controller session ACL/user-role | Явный отказ `ARUBAOS_CONTROLLER_UNSUPPORTED` |
| Juniper Junos/SRX | Адаптер не подключён |

Расширение файла и имя устройства не выбирают парсер: решает содержимое.
Замаскированные `ipN`/`ip#N` остаются unknown; автоматической подстановки адресов нет.
Подробности: [SUPPORTED_PLATFORMS](SUPPORTED_PLATFORMS.md).

### Очередь и отмена

Счётчик показывает завершённые файлы, а не процент разбора текущей конфигурации.
«Отменить ожидающие» отменяет задания, которые ещё не начали выполняться.
Текущий анализ завершается по возможностям ядра. После закрытия окна история
запущенного пакета может иметь состояние interrupted; поздние UI callbacks не вызываются.

## 3. Обзор и охват проверки

Обзор показывает дату последней проверки, количество всех
уникальных устройств проекта и небольшую таблицу производителей с количеством
устройств. Устройства считаются по подтверждённому/выбранному ID во всей истории,
а не по числу файлов последнего запуска. Для каждого устройства используется
его последний разобранный снимок, включая частичный. Ошибки импорта не создают
устройства и не удаляют предыдущий пригодный снимок. Это устройства проекта,
а не активные подключения к оборудованию.

Охват и находки последней проверки показываются отдельно от общего инвентаря.

Проверьте одновременно количество обработанных файлов, partial/unsupported/error,
полноту каждой проверки и количество находок по критичности.

| Значение | Что означает |
|---|---|
| Выполнена в поддержанной области (`complete`) | Проверка выполнена в своей явно ограниченной области |
| Выполнена частично (`partial`) | Проверена доступная часть, но есть неизвестные или неподдержанные условия |
| Не выполнена (`partial` и `CHECK_NOT_EXECUTED`) | Нет пригодной области для выполнения; причина указана рядом с проверкой |
| Не применима (`not_applicable`) | Проверка неприменима в данной области |
| unsupported | Парсер не смог сформировать поддержанный результат |
| error | Файл не прочитан или операция не завершена |

Ноль находок не означает безопасность сети. Management/SNMP/control-plane ACL
не являются транзитной политикой. Coverage относится к обнаруженным конструкциям,
а не проценту доказанной защищённости оборудования.

Карточка устройства и раздел «Отчёты» показывают причины ограничений каждой
проверки. HTML сохраняет те же различия. В JSON исходные статусы совместимы:
«Не выполнена» определяется по коду `CHECK_NOT_EXECUTED`, а не по нулю находок.
Предупреждение об ограниченной поддержке платформы остаётся видимым, но само по
себе не отключает сравнение полностью разобранных ACL с известным порядком и
областью. Неполные ACL требуют отдельных ограничений и не считаются доказанно
проверенными.

## 4. Находки и решения пользователя

В «Анализ → Проблемы» доступны область (проект или запуск), устройство, проверка, поиск, критичность и статус. Полнота проверок показана отдельно от списка находок. Выберите строку — справа
появятся объяснение, рекомендация, полнота проверки, evidence и сохранённые фрагменты.
Сортировка таблицы сохраняет связь с правильной находкой. Панели разделены
перетаскиваемым разделителем.

На вкладке «Решение» выберите статус, заполните комментарий и нажмите «Применить к выбранным».
Для массового изменения выберите несколько строк через Ctrl/Shift.
Статусы `new`, `confirmed`, `in_progress`, `accepted_risk`, `false_positive`,
`resolved` — решения пользователя. Они не меняют исходный результат, severity или
полноту проверки. Статусы и комментарии сохраняются только для данного запуска;
новый запуск не наследует их автоматически.

## 5. Устройства, правила и исходники

В «Инфраструктуре» доступны поиск, фильтры источника, платформы и типа, а также две области:
«Импорты выбранного запуска» показывает все его файлы, включая ошибки;
«Все ресурсы проекта · последние снимки» — последние разобранные устройства и наблюдения облачных ресурсов. Время и источник каждого снимка сохраняются; отсутствие ресурса в новом облачном сборе не означает удаление. Таблица содержит платформу, состояние и диагностику.
Выберите устройство и вкладку «Источники» для отдельных действий:

- «JSON отдельного результата» сохраняет прежний `FirewallAssuranceResult 1.0.0`.
- «Подключить исходник» после перезапуска читает явно выбранный файл и проверяет
  SHA-256. Совпадающие байты восстанавливают исходную сессию даже при другом имени.
- «Повторить проверки» использует подключённый снимок и создаёт новый запуск.
- В полях «Строки подключённого исходника» задайте начало/конец и нажмите
  «Показать фрагмент». Просмотр ограничен проверенным снимком и 200 строками.

При другом SHA-256 программа не принимает файл как доказательство старого анализа.
Изменившийся файл добавляется в подготовку отдельного запуска; старый снимок сохраняется.
Ошибка чтения или отсутствующий файл не создаёт такую подготовку. Файловое время не считается
временем наблюдения состояния устройства.

В карточке доступны «Сведения», «Правила», «Объекты», «Проблемы», «История» и «Источники». Из проблемы можно открыть связанные правила и доказательство. Для облачных ресурсов проверка ACL пока недоступна; данные API доступны в карточке и исходной операции. Двойной щелчок по истории открывает выбранное наблюдение.
«Анализ → Правила и объекты» показывает нормализованный инвентарь с поиском
по всем устройствам проекта; можно переключиться на выбранный запуск. Выбор строки
открывает исходную модель справа. Unknown/resolution_status не интерпретируются
интерфейсом как any или безопасные значения. Полный исходник не восстанавливается
из нормализованной модели.

## 6. История

Облачные подключения находятся в «Настройки → Интеграции → Cloud.ru».
Получение данных: «Операции → Облачный сбор → Новый сбор». На вкладке «Результат»
доступны выбор сохранённого сбора, ресурсы, ошибки, API-запросы и JSON-экспорт.
Сбор не запускает локальные проверки ACL. Инструкции:
[VMware](CLOUD_RU_VMWARE.md), [Advanced/Evolution](CLOUD_RU_PUBLIC.md).

На «Операции → История» выберите запуск и нажмите «Открыть выбранный запуск», либо откройте
строку двойным щелчком. Результаты, инвентарь, сохранённые выдержки и решения
доступны без повторного чтения исходников.

В истории отдельно обозначены проверки и облачные сборы. Для сравнения находок выделите два запуска проверок Ctrl/Shift и нажмите «Сравнить два выбранных».
Сравниваются устройства, проверки и rule IDs: появились, продолжают наблюдаться,
не наблюдаются. Отсутствие находки не доказывает устранение; смена rule IDs может
создать видимость новой находки. Это не сравнение фактического сетевого доступа.

## 7. Общий отчёт

Откройте «Отчёты» и выберите нужный запуск в верхнем списке:

1. Решите, включать ли сохранённые фрагменты конфигураций. По умолчанию они включены.
2. Нажмите «Сохранить HTML» или «Сохранить JSON» и выберите путь.
3. HTML откройте любым браузером: интернет не нужен. Для печати используйте Ctrl+P;
   отчёт имеет светлое оформление печати.

HTML содержит управленческую сводку, охват/ограничения, устройства, находки,
пользовательские комментарии/статусы и технические доказательства. Неподдержанные
файлы и ошибки также включены. Все исходные значения экранируются.

JSON имеет `package_type: firewall-compliance.batch-report`, `schema_version: 1.0.0`.
Отдельные исходные отчёты находятся в `items[].result`; пользовательские решения —
в `user_decisions`. Он не является полным резервным архивом проекта. Автоматического
восстановления проекта из экспортированного пакета нет.

Исключение фрагментов убирает текстовые выдержки, но структурированные evidence,
адреса и другие значения исходного backend-отчёта остаются. Проверяйте содержимое
перед передачей отчёта другому человеку.

## 8. Расширенный анализ ASA

Раздел «Анализ → Расширенные инструменты» доступен для реальных ASA-сессий текущего окна. После перезапуска сначала
подключите исходник. HP/Aruba/Comware не становятся ASA-базой.

Доступны пять вкладок: сетевые документы, интерфейсы/маршруты, маршрут/локальная ACL,
forwarding ASA, результаты/JSON. Metadata, observation и основание полноты задаются
явно. Эти поля не исполняют команды на оборудовании.

Документы и дополнительные сетевые результаты живут в памяти до закрытия окна;
экспортируйте их оригинальный JSON отдельно. Они не включаются автоматически в общий
policy HTML. Итоговая достижимость, effective NAT/PBR и полная цепочка не вычисляются.
Примеры и значения полей: [NETWORK_UI_GUIDE](NETWORK_UI_GUIDE.md).

## 9. Где хранятся данные

По умолчанию: `%LOCALAPPDATA%\FirewallCompliance\projects.sqlite3`.
База содержит проекты, настройки, историю, нормализованный инвентарь, SHA-256,
сведения об источниках, находки, marks и ограниченные выдержки доказательств.
Полные файлы конфигураций в БД не копируются. Для каждого импорта сохраняются
до 40 строк выдержек: до трёх строк на уникальный диапазон, до 4096 символов на фрагмент.

БД не обезличена и не зашифрована приложением: нормализованные данные и выдержки
могут быть чувствительными. Для резервной копии закройте приложение и скопируйте
папку `FirewallCompliance`. Удаление папки удалит историю и настройки; исходные
конфигурации и явно экспортированные отчёты останутся в своих местах.

## 10. Если результат не появился

- `PARSER_NOT_FOUND`: проверьте формат по матрице, а не расширение файла.
- `ARUBAOS_CONTROLLER_UNSUPPORTED`: controller session ACL сейчас не поддержаны.
- Кнопка анализа недоступна: дождитесь определения и подтвердите неоднозначные устройства.
- Таблица находок пуста: сбросьте поиск/фильтры и проверьте diagnostics/полноту.
- Нет ASA-базы: откройте соответствующий запуск и подключите исходник с тем же SHA-256.
- Hash не совпал: сохраните новый анализ отдельно, не подменяйте старое доказательство.
- Из portable исчезли библиотеки: распакуйте всю папку `_internal` вместе с exe.

Технические границы и проверки: [DESKTOP_UI](DESKTOP_UI.md), [CURRENT_STATE](CURRENT_STATE.md).
