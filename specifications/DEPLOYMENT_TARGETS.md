# Целевые платформы поставки

Обновление 21.10.2026: текущий каталог новой поставки — prod/FirewallCompliance, архив — prod/FirewallCompliance-windows-x64.zip.
Контуры DEV/TEST/PROD и проверка выпуска описаны в [ENVIRONMENT_SEGMENTS.md](ENVIRONMENT_SEGMENTS.md).

## Первичная платформа

Первая целевая платформа продукта - локальный запуск на рабочей станции пользователя под Windows 10 или Windows 11 x64. Это требование поставки, а не подтверждение коммерческой поддержки всей матрицы ОС: portable собирается локально; проверки всей матрицы чистых машин ещё не подтверждены.

Продукт запускается в контролируемой локальной среде и по умолчанию не требует доступа к сети, облаку или отдельному серверу.

## Требования первой поставки

- Основной пользовательский сценарий доступен без прав локального администратора.
- Входные конфигурации обрабатываются на рабочем ПК пользователя.
- Результаты, временные файлы и локальная БД сохраняются в явном пользовательском каталоге, а не рядом с исполняемым файлом и не в системных каталогах.
- Путь к данным и папке отчётов настраивается пользователем.
- Поставка имеет фиксированную версию, контрольную сумму и список зависимостей.
- CLI является обязательным интерфейсом первой поставки; локальный web UI не является требованием MVP.
- Не требуется установка Docker для основного локального сценария.

## Формат поставки

Целевой вариант для первой версии: подписываемый Windows-дистрибутив с bundled Python runtime либо управляемый portable package. Конкретный механизм упаковки выбирается отдельным ADR после проверки совместимости с зависимостями визуализации и требованиями ИБ.

Текущий запуск выполняется из окружения разработки через `uv`; первоначальное получение runtime и зависимостей может требовать сети. Офлайн-обработка уже загруженного файла не означает готовности офлайн-установки.

Основной desktop использует PySide6 / Qt (TASK-012, ADR-018). Из исходников после
`uv sync --all-groups` запускается через `Start-Desktop.cmd` или модуль desktop.
`scripts/build_desktop.ps1` создаёт PyInstaller onedir portable:
`dist\FirewallCompliance\FirewallCompliance.exe` с runtime/Qt в `_internal`.
Переносить нужно всю папку. Рабочая БД располагается в
`%LOCALAPPDATA%\FirewallCompliance\projects.sqlite3`, отчёты — в явно выбранных файлах.
Полные конфигурации не копируются; normalized данные/выдержки могут быть чувствительными.
Порядок работы: [USER_GUIDE.md](USER_GUIDE.md). Испытания сборки: [CURRENT_STATE.md](CURRENT_STATE.md).

Build script временно ограничивает PATH системными Windows-каталогами и `.venv\Scripts`,
затем восстанавливает исходный PATH. Это исключает случайный захват сторонней ICU DLL:
в ранней сборке DLL из другого инструмента имела несовместимые symbols с Qt.
Тестовые/dev-модули, Tkinter и неиспользуемые QtWebEngine/PDF исключены из поставки.

Приёмка дистрибутива: установка или распаковка и анализ synthetic fixture на чистых Windows 10 и Windows 11 x64 без сети, без установленного Python/uv/Docker и без прав администратора. Runtime и зависимости фиксируются, входят в поставку либо в заранее проверенный офлайн-комплект и сопровождаются хешами/SBOM. Поддерживаемые сборки ОС и допустимые варианты поставки фиксируются в ADR; результаты испытаний сохраняются отдельно.

## Отложенные платформы

- Linux server deployment и Docker Compose относятся к следующей стадии.
- macOS не входит в поддерживаемую матрицу MVP.
- Многопользовательский web deployment, PostgreSQL, SSO и серверные очереди не входят в первую локальную поставку.
