# Список задач

## Правила приоритизации

- P0: необходимо для достоверного ядра анализа.
- P1: необходимо для коммерчески полезного MVP.
- P2: ценно после стабилизации ядра.
- P3: возможность для будущих версий.

Первый срез backend карты заданных условий ACL на существующих
результатах HP/Aruba AOS-Switch (AOS-S)/AOS-CX и Comware выполнен (ADR-020).
Полный этап карты открыт: хранение, сетевые фильтры, HTML/PNG и пакетный охват. Это не
effective reachability и не добавление поддержки производителей. UI карты ведётся
в отдельном чате. Новые работы по Cisco ASA/IOS/XE отложены до отдельного решения;
существующие реализации, registry и tests сохраняются, завершённые задачи ниже
остаются историей выполненной работы.

## Отложено: развитие Cisco до отдельного решения

- [ ] Подготовить evidence-based effective NAT/PBR вход Cisco ASA/IOS/XE, включая
  системный NAT, и application-композицию evaluator с подтверждённым выбором маршрута.
- [ ] Расширить Cisco adapters и сетевые факты ASA/IOS/XE; отдельно рассмотреть
  перенос ветки Cisco IOS ACL старого универсального парсера.
- [ ] Развивать Cisco network paths и итоговую достижимость после подтверждения
  необходимых фактов и семантики.

Эти задачи исключены из новых активных работ и не являются зависимостью следующего
среза карты ACL. Отсрочка не требует удаления существующего кода, registry или tests
и не отменяет уже завершённые Cisco-задачи.

## Вне текущего roadmap

Vulnerability Control, управление векторами атак и Change Management с согласованием/применением политик не являются обязательными задачами последующих фаз. Их включение возможно только после отдельного продуктового решения. Экспорт findings во внешнюю систему сам по себе не реализует эти вертикали.
