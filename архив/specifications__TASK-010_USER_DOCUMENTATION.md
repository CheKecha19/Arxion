# TASK-010: Актуализация документации и пользовательские руководства

Дата: 2026-10-10. Статус: Готово.

## Цель

Описать использование подключённого desktop UI и согласовать текущий статус проекта
с фактической реализацией TASK-009.

## Контекст

PRODUCT_VISION, ARCHITECTURE, DEVELOPMENT_RULES, ROADMAP, REQUIREMENT_STATUS,
UI_BACKEND_INTEGRATION, DESKTOP_UI и ADR-016. Затронуты описания FR-001/003/030/021/022;
границы SR-005/006 и Network Assurance сохранены.

## Область задачи

- Основной USER_GUIDE: установка, запуск, режимы, очередь, ID, все экраны,
  evidence/check statuses, JSON, повтор checks, diff, сессия и troubleshooting.
- NETWORK_UI_GUIDE: пять вкладок, metadata/observation, импорт, query/binding,
  forwarding, экспорт и воспроизводимые synthetic примеры.
- README, навигация, текущий статус, требования, roadmap/backlog, архитектура,
  стек, поставка, безопасность и политика платформ.
- Устранение дублирующегося номера ADR-015: forwarding сохраняет ADR-015,
  desktop получает ADR-016; содержание принятых решений не изменено.

## Вне области задачи

- Изменение кода, интерфейса, зависимостей, контрактов и версии приложения.
- Новые parsers/evaluator, постоянная история, установщик, реальные данные заказчиков.

## Критерии приёмки

- Надписи и поведение инструкций сверены с текущим исходным кодом.
- Есть пошаговый первый запуск на policy_quality.cfg и полные JSON-примеры для сети.
- Неполные fixtures не получают вымышленных observation/complete/terminal.
- Различия UI-статусов, backend-статусов, отчёта и полной сессии объяснены.
- Локальные ссылки доступны, JSON синтаксически корректен, номера ADR уникальны.

## Проверка

- Unit tests: новые не требуются, поведение продукта не менялось.
- Integration/golden tests: повтор полного прогона не выполнялся для документации;
  прежние 1164 passed относятся к TASK-009, а не к этой задаче.
- Сверка с launcher, desktop controllers/views, моделями и существующими тестами.
- Шесть JSON-блоков NETWORK_UI_GUIDE извлечены из документа и проверены через
  backend на существующих synthetic fixtures. UUID policy source подставлен из
  действительного NetworkImportResult; положение access-group сверено с файлом.
- Проверены import (2 interfaces / 2 configured routes / 4 RIB), route/reachability,
  interface/policy/device и forwarding; исходные network/forwarding JSON прошли roundtrip.
- Проверка Markdown-ссылок по README, tests/README и specifications; отсутствующих нет.
- Проверены синтаксис всех шести JSON-блоков и уникальность ADR-001–016.

## Безопасность и обработка данных

Использованы только уже существующие synthetic fixtures. Исходные данные не изменены,
реальные конфигурации не читались и не копировались. Временные значения наблюдения и
подтверждения полноты для достижения желаемого результата не выдумывались.

## Зависимости и риски

После изменения названий экранов, полей или схем необходимо одновременно обновлять
оба пользовательских гайда. Конкретные UUID генерируются в сессии; в примере binding
пользователь заменяет обозначенный placeholder UUID исходного policy-документа.
