# Текущее состояние

Актуализировано 31.10.2026 по исходникам коммита `c170560`; версия приложения **0.3.2**.

## Реализовано в текущем приложении

- Qt desktop и CLI, проекты SQLite, история ревизий и решений по находкам, накопленный реестр инфраструктуры.
- Стандартный каталог: Cisco ASA, HP/Aruba, Comware, UserGate и Ideco. Поддержка экспериментальная и ограниченная; точные границы — [SUPPORTED_PLATFORMS](SUPPORTED_PLATFORMS.md).
- UserGate и Ideco: сбор через API с последующим анализом собственных JSON-снимков. Реальная совместимость прошивок не подтверждена.
- Cloud.ru VMware: сбор ресурсов и анализ NSX-T Edge Firewall; Advanced/Evolution — сбор инвентаря и Security Groups, без общего анализа SG.
- 27 определений проверок: 15 policy и 12 management. Выбор зависит от входных данных, профиля и сценария; наличие определения не означает выполнение для каждой платформы.
- Общий AnalysisResult, JSON/CSV/HTML; ACL-карта с фильтрами, архивом SQLite, CLI и экспортами JSON/DOT/HTML/PNG; технические контроли и governance-сценарии.
- Код платформ разнесён по `devices`, проверок — по `checks`; старые импорты сохранены. UserGate/Ideco пока находятся в `parsers`/`infrastructure`. AOS-Switch/AOS-CX используют общую грамматику вендора.
- Отложенный запуск Qt: окно до загрузки проекта, фоновое чтение, общий снимок истории и заполнение скрытых страниц по запросу. Количественное ускорение не измерено.
- Единая поставка `dist/FirewallComplience_v0.3.2`; ZIP и отдельная CLI-поставка автоматически не создаются. См. [WINDOWS_DISTRIBUTION](WINDOWS_DISTRIBUTION.md).

## Ограничения и подтверждения

Полная сквозная достижимость, effective NAT/PBR, DFW и гостевые NGFW облака не подтверждены. ArubaOS controller имеет отдельный экспериментальный парсер, но не включён в стандартный каталог; Juniper не подключён. Policy/NAT/object diff содержит отдельный код, но не считается завершённым интегрированным сценарием.

Последняя записанная Windows-сборка 0.3.2 завершилась успешно без запуска приложения; это не подтверждение runtime. Результат старой packaged-самопроверки 0.3.0 нельзя переносить на 0.3.2.

Для текущего коммита [GitHub Actions](https://github.com/CheKecha19/Arxion/actions/runs/41107886303): карты/архитектура и Python packaging успешны; quality, tests, smoke и security неуспешны. Причины здесь не переаттестованы. CI-сводка относится к этому запуску, а не ко всем будущим версиям.

До v1.0 новые тесты создаются только по запросу; автоматические проверки выполняются в CI. Локальный запуск требует прямого запроса — [AGENTS.md](../AGENTS.md).

## Условная цепочка политик: TASK-008, ADR-019

Реализован `analysis/forwarding_policy.py: evaluate_forwarding_policy(context, *,
ingress_interface_id, egress_interface_id)`. Проверяются профиль, применимость,
полные inventories и absence NAT/PBR/exceptions; объясняются same-security,
ingress/global/outbound ACL и конец цепочки. Неизвестные данные не получают defaults.
Физический egress задаётся условно вызывающей стороной, не выбирается из RIB.

ForwardingPolicyResult 0.1.0 сохраняет context snapshot, восемь этапов trace,
policy_status и причины. Верхний status всегда unknown/not_enough_evidence:
runtime_pending обязателен. Чтение JSON и model_copy повторяют полный расчёт.
Доменная алгебра matcher и сервис расчёта не импортируют другие слои; прежние
analysis imports совместимы. UI и SQLite этим срезом не менялись.

Работа выполнена с агентом тестирования и независимым статическим ревью. Три
замечания закрыты регрессиями: продолжение после terminal deny, stale allow при
замене контекста и несовместимая грамматика maintenance-версий. Добавлены 110 unit,
девять integration и восемь golden tests. Проверки: pytest 1457 passed, Ruff
format/check - 172 файла, mypy - 73 source files. Прежние 28 JSON golden неизменны
по SHA-256; восемь новых утверждены явными командами после просмотра кандидатов.
Полный pytest выполнялся с разрешением вне Windows sandbox во временной папке проекта.

Все прежние конфигурационные forwarding excerpts остаются неполными; current parser
оставляет effective NAT unknown. Положительные эталоны имеют собственные полные
синтетические доменные доказательства, не являются аппаратным подтверждением.
Отложенный Cisco backlog: application-композиция с подтверждённым маршрутом и
подготовка отдельного effective NAT/PBR входа. Полный путь, operational state и
итоговая достижимость открыты; это не ближайший активный шаг.

Регрессии меню, накопительного инвентаря и существующий полный набор:
1239 тестов passed; Ruff и mypy (67 source files) успешны.

## Исторический срез ядра до Qt: forwarding вход 8.2

Есть локальный CLI, экспериментальный ASA ACL adapter 0.2.0, сетевой и forwarding adapters 0.1.0, ревизии, структурный diff и семь checks Firewall Assurance. Network Assurance содержит импорт, routing decision и локальные API evaluate_policy/evaluate_interface/analyze_device_decisions. Application analyze_imported_device проверяет mapping label/interface и сохраняет source evidence. Новый конфигурационный forwarding вход нормализует интерфейсы, ACL и in/out/global bindings с source mapping и диагностикой; application binding этого контекста ещё отсутствует. Полная ACL chain, семантика NAT/PBR, operational state, итоговая достижимость, сетевой CLI, общий AnalysisResult и постоянное хранение пока отсутствуют. UI разрабатывается отдельно; этот срез его не меняет.

Git и удалённый репозиторий отложены до решения о публикации; Windows CI workflow подготовлен, но удалённый CI не запущен. Используются только synthetic fixtures. Матрица выполнения FR: `REQUIREMENT_STATUS.md`.

Шаг 8.0 закрывает SR-001–SR-004: DeviceRevision 2.0.0 публикуется как глубокий snapshot, IP интерфейса сохраняет хостовую часть, сетевые наборы имеют CollectionEvidence, наблюдение отделено от времени файла/получения/импорта. Доказанно пустой набор не смешивается с неизвестным. Старый JSON читается с понижением достоверности и миграционной диагностикой.

ADR-009/010 и NETWORK_INPUTS определяют контракт и будущие сетевые входы ASA 9.16. Подготовлены три synthetic сценария, восемь payloads с SHA-256; все RIB - выдержки. Это не новый сетевой parser adapter. Шаг 8.1/ADR-011 добавил ReachabilityQuery, PathHop, RouteSelectionResult и ReachabilityResult 0.1.0, API select_route/analyze_reachability. Выбор по полной согласованной single IPv4/default RIB проверяет LPM, явные AD и сравнимую metric; сохраняет равные кандидаты и причины неопределённости. Итоговые reachable/blocked ещё запрещены, включая routing no_route/blackhole, пока не проверены NAT/PBR и policy. SR-005 (структурный diff) и SR-006 (общий provenance результата) остаются открыты.

Входной срез 8.2/ADR-012 реализован: SourceDocument и NetworkDocumentMetadata проходят повторную валидацию и проверку SHA-256; полнота и наблюдение не угадываются. Настроенные маршруты сохраняются отдельно от RIB; частичная RIB не дополняется конфигурацией. Привязки маршрутов используют только известные интерфейсы согласованного наблюдения. Исходная ревизия не изменяется; результаты являются глубокими snapshots. Восемь исходных сетевых payloads остаются выдержками, а complete-сценарии тестов не являются аппаратными экспортами.

Последняя полная проверка после конфигурационного ASA forwarding adapter: pytest - 1130 passed; Ruff check/format успешны (126 Python файлов на момент проверки), mypy - 51 source files. Добавлены 10 тестов входного/выходного контракта, 45 unit adapter, девять integration и восемь golden tests. Восемь новых JSON-эталонов утверждены явной командой; двадцать прежних побайтно неизменны по SHA-256. CLI smoke сохраняет schema 1.0.0/parser 0.2.0, семь checks и 14 findings. Используется .uv-cache-phase8; pytest запускался с разрешением вне sandbox в .pytest-tmp-phase8-verified внутри проекта. Прежние схемы, CLI, зависимости и UI не менялись.

ADR-013 закрепляет локальные решения 0.1.0: полнота и mapping требуют явных оснований, tuple задан как acl_input, не восстановлен из NAT. No_match не равен implicit deny до подтверждённого конца цепочки. Административное enabled не является operational up. Составной результат допускает только unknown/not_enough_evidence.

## Исторический baseline прототипа

Исходный проект является функциональным прототипом для офлайн-анализа firewall-конфигураций. В нём есть парсеры, базовые нормализованные модели, построение графов и топологии, security/compliance-эвристики, diff и отчёты HTML/PNG.

## Сильные стороны исходного прототипа

- Есть основы multi-vendor parsing для UserGate, Cisco, Juniper, Huawei и частично HP/Aruba.
- Сквозной CLI pipeline формировал локальные HTML-, PNG- и JSON-результаты.
- В коде присутствуют компоненты security audit, config diff, topology и reachability.
- Документация описывает более широкий вектор визуализации v3.0.

## Пробелы исходного прототипа

- Тесты в основном представлены fixtures; поведение парсеров, семантического анализа и отчётов не защищено полным автоматизированным набором.
- README, CLI и реализация имеют расхождения; reachability присутствует в ядре, но не полностью подключён как CLI workflow.
- Крупные модули совмещают несколько обязанностей, особенно ACL parsing и HTML visualization.
- Покрытие парсеров и неподдержанные конструкции измеряются и показываются непоследовательно.
- Security и compliance-результатам нужна единая evidence-centric модель жизненного цикла.
- Auto-install в `main.py` не подходит для production packaging.

## Текущее направление

Не переписывать исходный код вслепую. Сохранить его как поведенческий ориентир, создать модульный фундамент, ввести тесты и канонические контракты, затем переносить функциональность вертикальными срезами.

## Конвенции проекта

## Состояние спецификаций

Фаза 0 подготовлена документально: определены видение, функциональные и качественные требования MVP, политика поддержки платформ, словарь и временный security baseline. Первая production-quality платформа выбрана ADR-005 с обязательным quality gate.

Фаза 1 завершена для доступного исходного прототипа. Контрольные значения fixtures, разрывы реализации и карта миграции зафиксированы в `LEGACY_BASELINE.md` и `LEGACY_MIGRATION_MAP.md`.

Фаза 2 завершена: создан новый Windows-ориентированный пакет `firewall_compliance`, зафиксированы зависимости через `uv.lock`, настроены Ruff, mypy, pytest и Windows CI. Проверки успешно пройдены; подробности - в `TASK-001_PROJECT_FOUNDATION.md`.

Фаза 3 завершена: реализована каноническая Pydantic-модель для конфигураций, устройств, правил, сетевых объектов, findings, evidence и результатов парсинга. Валидация и сериализация защищены 20 unit-тестами; подробности - в `TASK-002_DOMAIN_MODEL.md`.

Фаза 4 завершена: создан независимый от производителя parser-contract, registry, файловый инфраструктурный адаптер и полный нейтральный тестовый контур. Legacy-fixtures перенесены с контролем хешей; golden-результаты обновляются только явной командой. Ruff и mypy прошли, pytest выполнил 30 тестов. Подробности - в `TASK-003_PARSER_TEST_CONTOUR.md`.

Фаза 5 завершена для ограниченного Cisco ASA adapter с source mapping, coverage и тремя baseline fixtures; подробности - в TASK-005. Расширение Фазы 7 не означает коммерческой поддержки платформы.

## Завершённые срезы

Базовый срез Фазы 6 завершён: реализован `DeviceRevision` с моделями сетевых фактов и структурным diff. Его ограничения SR-001–SR-004 исправлены шагом 8.0; SR-005 остаётся открытым. Подробности - в `TASK-006_DEVICE_REVISIONS.md`, ADR-007/009.

Исторический этап Фазы 6 сам по себе не подтверждал готовность Network Assurance. Исправления модели подтверждены отдельными регрессиями; шаг 8.1 реализует только routing decision, не всю цепочку потока.

Фаза 7 завершена в ограниченной области: any-any, дубликаты, полное затенение одним правилом, кандидаты на объединение, логирование, описания и отключённые правила. Checks независимы от производителя; `FirewallAssuranceResult` сохраняет версии, параметры, parser diagnostics и статус полноты каждой проверки. Все новые findings связаны с конкретной ревизией и содержат Evidence. Сквозной локальный запуск доступен через `firewall-compliance analyze <файл>`; JSON выводится в stdout.

Cisco ASA parser adapter `0.2.0` хранит область/направление/first-match, полностью потребляет поддержанные условия и сохраняет диагностику unsupported/malformed конструкций. Добавлены synthetic сценарии, property, integration и golden tests. Ruff и mypy успешны, pytest - 214 passed. Подробности - в `TASK-007_FIREWALL_ASSURANCE.md`, ADR-008 и `SCHEMA_MIGRATIONS.md`.
