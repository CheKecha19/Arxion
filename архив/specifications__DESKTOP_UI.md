# Desktop Qt: проекты, анализ и отчёты

Исходниковая сверка: 31.10.2026, приложение 0.3.2. Базовые решения: ADR-018/TASK-012; исторические свидетельства испытаний не означают текущий успешный CI.
Пользовательские инструкции: [USER_GUIDE](USER_GUIDE.md), [сетевые сценарии](NETWORK_UI_GUIDE.md).

## Представление и граница

Основной desktop использует PySide6 / Qt Widgets. Цветовые роли: фон `#10131C`,
панель `#191F2D`, приподнятая поверхность `#242C3E`, текст `#E8EDF7`, вторичный
текст `#A8B3C7`, голубой `#79B8FF` и фиолетовый `#B7A0FF`. Кнопки/поля имеют
радиус 8 px, панели — 12 px. Таблицы используют `QAbstractTableModel` и proxy
для сортировки/поиска; выбор переводится в исходную модель до открытия подробностей.

С TASK-015 навигация содержит пять разделов: «Обзор», «Инфраструктура»,
«Анализ», «Операции», «Отчёты». Настройки закреплены внизу.
Анализ содержит проблемы, правила/объекты и расширенные инструменты.
Операции объединяют историю проверок и сборов, подготовку файлов и облачный сбор.
Облачный экран разделён на «Новый сбор» и «Результат»; формы прокручиваются.
Подготовка файлов больше не занимает постоянный инвентарь.

WorkspaceHistory сохраняет контекст запуска, фильтры, выбор и вкладки в памяти.
ResourceDetails связывает карточку с проблемами, историей и доказательствами.
workspace_models объединяет представление ресурсов и операций без миграции БД.
Облачные IDs разделены по подключению; имя/IP не является ключом объединения.
Отсутствие ресурса в новом сборе не удаляет прежнее наблюдение. Каждый ресурс
показывает собственное время получения; это не единый моментальный снимок сети.

Проблемы проекта берутся из последних снимков устройств. Пользовательские решения
записываются в исходный запуск конкретной находки. Выбор исторического запуска
не меняет обзор последней проверки. Отчёт имеет явный выбор запуска.
Завершение анализа сохраняет текущую страницу; уведомление открывает результат
конкретной завершившейся проверки. Карта ACL уже подключена: фильтры, SQLite-архив, batch, HTML/PNG и переходы к правилам.

CLI и доменные контракты не меняются. Tkinter-модули сохранены как историческая
реализация и отдельный прежний smoke; штатный entrypoint выбирает Qt.

## Оркестрация

`backend.py` создаёт согласованную `AnalysisSession` из однократно прочитанного
`SourceDocument`, `ParseResult`, `DeviceRevision` и `FirewallAssuranceResult`.
Каталог выбирает ASA / HP-Aruba / Comware / UserGate / Ideco по содержимому. Juniper не подключён;
ArubaOS controller session ACL возвращает явный отказ.

`jobs.py` выполняет операции в одном daemon Python worker; Qt получает callbacks
через timer/poll в GUI-потоке. Выполняющийся анализ не имеет кооперативной отмены:
отменяются только ожидающие задания. Закрытие запрещает позднюю доставку UI callbacks.
Количество завершённых файлов измерено; процент выполнения внутри файла не выдумывается.
Tk-specific GC guard в Qt не используется.

## Постоянные проекты

`project_store.py` хранит SQLite по умолчанию в
`%LOCALAPPDATA%\FirewallCompliance\projects.sqlite3`; API принимает явный путь
для тестов и изолированных экземпляров. Таблицы проектов, запусков, импортов,
отметок и подтверждённых соответствий устройств разделены; текущая версия БД — 1.
Это локальный desktop repository. Общий AnalysisResult также сохраняется, но исходные policy/network модели остаются отдельными контрактами.

`list_project_devices(project_id)` получает последний report-bearing снимок каждого
уникального `report.device_id` среди всех запусков проекта. Частичные снимки видимы,
а ошибки, отменённые и неподдержанные файлы не создают устройства и не заменяют
предыдущий пригодный снимок. Возвращаются оригинальные payload/import ID и run ID;
схема БД не меняется. Главная считает устройства и производителей по этому инвентарю,
отдельно показывая охват последней проверки. Устройства и правила имеют выбор между
проектом и конкретным запуском; карточка содержит сведения, правила, объекты, проблемы, историю и источники.

Сохраняются настройки запуска, исходный отчёт, нормализованный parse result и revision,
диагностика, SHA-256, сведения об источнике и отдельные решения пользователя.
Полные source bytes не сохраняются. Выдержки берутся только из finding evidence:
до трёх строк на уникальный диапазон, общий бюджет 40 строк на импорт и до 4096
символов на фрагмент. Данные БД всё равно могут содержать чувствительные адреса и
значения нормализованных объектов; отсутствие полного исходника не обезличивает БД.

`attach_source` читает явно выбранный файл и проверяет SHA-256. При совпадении
восстанавливаются сохранённые IDs, revision и report, а имя источника остаётся
исходным даже при переименованном файле. При различии файл не подменяет доказательство;
требуется новый запуск. После закрытия полный просмотр исходника и повторные checks
требуют такого подключения. Связи устройств запоминаются после подтверждения пользователя.

## Пользовательские решения и история

Статус и комментарий хранятся отдельно от `FirewallAssuranceResult`, с привязкой
к запуску/finding ID. Массовое действие не переписывает check status или severity.
Новый запуск не наследует marks предыдущего автоматически. История переходов решений хранится отдельно и доступна в Qt.

Сравнение запусков сопоставляет device ID, check ID и rule IDs. «Не наблюдается»
не означает «устранено»; смена идентификаторов может выглядеть как новая находка.
Это обзор различий findings, а не semantic effective-access diff. Отдельный SR-005 diff сетевых данных уже разделяет значения, полноту и происхождение.

## Экспорт

`batch_reports.py` собирает пакет `firewall-compliance.batch-report`, schema `1.0.0`.
Он содержит сводку импорта, состояние/настройки запуска, diagnostics и исходные
`FirewallAssuranceResult` в `items[].result`; решения пользователя — в
`user_decisions`. Полные normalized revisions и локальные paths в пакет не включаются.
Отдельный JSON результата сохраняет прежний schema `FirewallAssuranceResult 1.0.0`.

HTML автономный, UTF-8, без JavaScript и внешних ресурсов; все значения экранируются.
Он содержит управленческую сводку, полноту и ограничения, устройства/находки,
решения пользователя и технические доказательства. Print stylesheet даёт светлое
оформление. Фрагменты включены по умолчанию и могут быть исключены из обоих форматов.
Отключение фрагментов не удаляет структурированные evidence из исходного отчёта.

## Расширенный ASA

`qt_network.py` переносит существующие операции из `network_backend.py`: импорт
документов в новую revision, инвентарь, route/reachability/interface/policy/device
queries и отдельный forwarding parser. Metadata, observation и completeness
заявляются явно; дата импорта не заменяет время наблюдения устройства.

Источники, drafts и сетевые результаты находятся в памяти окна. Они экспортируются
оригинальными backend-моделями, но не добавляются автоматически в общий policy HTML.
После перезапуска для ASA-базы сначала нужен исходник с совпадающим SHA-256.
Configured routes не являются RIB; selected route и одна allow ACL не являются
итоговым reachable. Effective NAT/PBR и полная цепочка не вычисляются.

## Дополнения текущего desktop

- Общий AnalysisResult: сохранение/открытие в проекте и экспорт JSON/CSV/HTML.
- ControlsPanel и GovernancePanel: профильные оценки и история в пределах доказанного scope.
- Сборщики UserGate/Ideco: явное подключение через настройки/файловые операции,
  новый JSON-снимок для обычного анализа. Пароли не сохраняются в снимке.
- VMware Edge: анализ сохранённого сбора/автоматически после сбора; Advanced/Evolution — инвентарь.
- Реестр инфраструктуры накопленный; отсутствие в новом сборе не удаляет ресурс,
  архивирование скрывает его из активной карты с сохранением истории.
- Deferred startup показывает окно до чтения storage/project. Общий ProjectSnapshot
  уменьшает повторное чтение истории; скрытые страницы/карты заполняются при переходе.
  Это исходниковое изменение, без нового замера времени запуска этой сверкой.

## Историческая проверка

`tests/integration/test_qt_models.py` проверяет связь proxy selection с payload,
reset/поиск и контраст двенадцати пар текстовых/фоновых токенов не ниже 4.5:1.
Storage/export tests проверяют перезапуск, отдельные marks, hash guard и экранирование.
Оконный `scripts/qt_desktop_smoke.py` использует synthetic fixtures и временную БД.
Подтверждённые результаты и ограничения испытаний сборки — в [CURRENT_STATE](CURRENT_STATE.md).
